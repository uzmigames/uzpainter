# 166. The void padding probes are re-authored as `-v2` on ramp files named `uv-ramp-n<N>`, and `srgb-bitmap-variants-v2` records the user-channel refusals

**Status**: accepted
**Date**: 2026-10-12
**Related Tasks**: phase1.25_pilot-wand, phase1.15_compositor-colour-fits

## Context

Decision 160 voided ten padding probes and refused `srgb-bitmap-variants`:

- In `export-padding-tie-2048` and the nine `export-padding-ramp-{r1,r2,r15}-{p0,p25,p75}`, User0 exported a uniform (1, 1, 1). Painter named the imported `uv-ramp-1024.exr` and `uv-ramp-2048.exr` as `uv-ramp`, and the projection capture raised on a missing UV transformation. `uv-ramp-512.exr` worked. The likely cause is that Painter reads a four-digit file-name suffix from 1001 up as a UDIM tile.
- `srgb-bitmap-variants` was refused at state step 33. Painter raised `ValueError: Invalid colorspace 'standard sRGB'` when the sRGB bitmap space was set on User1 (RGB8). The same space had worked on the sRGB8 channels.

The store keeps one record per golden id, and the admitted void manifests are immutable (`tier0_semantics write` refuses to change a recorded golden). New requests therefore need new names.

## Decision

1. **Renamed ramp fixtures.** `uv-ramp-n1024.exr` and `uv-ramp-n2048.exr` are generated by the committed `request_fixtures.uv_ramp`. Their bytes equal those of `uv-ramp-1024.exr` and `uv-ramp-2048.exr`. The old files stay, because the admitted void manifests name them. A test refuses any requested golden that imports an image whose stem ends in a number from 1001 up.
2. **`-v2` padding probes.** `export-padding-ramp-{r1,r2,r15}-{p0,p25,p75}-v2` and `export-padding-tie-2048-v2` keep decision 129's and decision 157's sequences step for step. Only the ramp input changes, to `uv-ramp-n<N>`. Their descriptions say so. The void rule of decision 129 still applies, and before admission the readback must name the resource `uv-ramp-n<N>`.
3. **`srgb-bitmap-variants-v2`.** It replaces the refused request, which is deleted because it was never recorded. The only change is s4. Each user channel takes its bitmap through `set_source` with no space. An attempted `SourceBitmap.set_color_space(sRGB)` follows (decision 156), so a refusal is recorded as `set_color_space.<step>` in the effective defaults rather than refusing the golden. That refusal is the answer for those channels. s0 to s3 and s5 to s8, the captures and the exports are unchanged.
4. `parity/RECORDER.md` §11.4 lists the eleven new names.

The model panel was not consulted. The caller fixed the scope, and each change has one reading.

## Alternatives Considered

- **Rename the old fixture files in place.** Rejected. The admitted void manifests name them by path and SHA-256, and those manifests are write-once.
- **Move the user channels to a colour space they accept.** Rejected. The question is what Painter does with sRGB on those channels, and the refusal answers it.

## Consequences

### Positive
- Eleven requests are ready for the next Legacy session, with no recorder changes.

### Negative
- Two fixture files are duplicated under new names, about 0.6 MB.
