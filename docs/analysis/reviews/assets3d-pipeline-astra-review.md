# Astra technical review — Assets3D pipeline and UzPainter requirements

Date: 2026-10-10. Scope: the eight Assets3D analysis documents and the UzEngine material/texture analysis.

## Executive summary

1. **Recommendation:** revise the analysis before accepting it as the architecture contract; it is useful evidence of the existing pipeline, but underspecifies the authorized replacement.
2. **Fact (P/README.md; P/.rulebook/decisions/001-acceptance-criterion-output-parity-with-substance-painter.md; current user brief):** the target is the same texture and render from the same instruction sequence, with native high-poly bake, Unreal ORM, UzEngine export, compact saving, Python and MCP.
3. **Recommendation:** make that output parity an explicit acceptance protocol; feature lists, approximate Iray/Cycles comparisons and generic procedural substitutes do not prove it.
4. **Fact (A/SM/18-Tunica/report.json → painting_v10.source_recovery):** approved tunic recovery requires different resources for C07 and F03 despite their shared historical mask name.
5. **Fact (A/SM/10-Chapeu/report.json → v8; A/Docs/Pipeline/Retopologia/chapeu-v6/paint/stack-hat-v8.json):** current hat evidence adds SpecularWeight and seven delivered maps; its stack has 43 layers and five groups.
6. **Recommendation:** retain external Blender maps and QA compatibility while making native bake, render parity and the requested engine presets mandatory product capabilities.
7. **Fact (U/runtime/tools/uzcook.cpp; U/runtime/shaders/runtime/gbuffer/gbuffer_ps.hlsl):** ORM ordering agrees, but normal compatibility remains route-dependent; opacity and Height/Thickness cooking need explicit contracts.
8. **Recommendation:** preserve source provenance, native precision, immutable baselines and separate technical, visual and user approval; this review grants no new asset approval.
