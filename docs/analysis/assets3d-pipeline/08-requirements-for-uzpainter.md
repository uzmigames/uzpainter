# 08 — Requirements for UzPainter derived from the Assets3D pipeline

Conventions as in [01](01-pipeline-overview.md): paths relative to `E:\UzmiGames\Assets3D\`, `SM/` = `Creatures/Undead/Skeletal Mage/Models3D/`, `UzPainter/…` and `UzEngine/…` = paths in those repositories.

Every requirement below is a **Recommendation (R)** derived from the **Facts** in files 01–07, which cite the original sources, or from the product owner's requirements; the "Trace" column points to the primary source, and **Owner** marks a product-owner requirement.

**Owner requirements** (stated 2026-10-09 and 2026-10-10; recorded in `UzPainter/README.md` and `UzPainter/.rulebook/decisions/001-acceptance-criterion-output-parity-with-substance-painter.md`): UzPainter must have Substance Painter's functionality (layers, smart materials, rendering, export, Python scripting, native MCP); bake from a high-poly mesh like Substance (AO, detailed normal and the other mesh maps); export PBR like Substance plus Unreal's ORM standard plus UzEngine's standard, preferably compressed; save progress compactly; fully replace Substance in the Assets3D pipeline. Acceptance: the same instruction sequence yields the same texture and the same render as Substance Painter.

Priorities: **MUST** = the owner requires it, or the current pipeline cannot run without it, or a binding pipeline rule demands it; **SHOULD** = used today on some pieces or needed to avoid a recorded failure; **COULD** = useful, not exercised by the pipeline today and not required by the owner. Owner requirements take precedence over pipeline habits: where today's pipeline does a job outside Painter (bake and GLB packing in Blender), that route stays supported but does not lower the priority of the owner-required capability. Revisions made after the technical review are listed in [09](09-review-response.md) §2. This file states needs, not a design.
