## 2. Architecture

| Aspect | Behaviour | Label | Source |
|---|---|---|---|
| MCP transport | FastMCP server over stdio (`mcp.run(transport="stdio")`), server name "Substance Painter" | Fact | `SRV` (`main`) |
| Painter transport | HTTP `POST http://<SP_MCP_HOST>:<SP_MCP_PORT>/run.json`, body `{"python": base64(code)}` or `{"js": base64(code)}`; Painter must run with `--enable-remote-scripting` (default `localhost:60041`) | Fact | `MCP\src\substance_painter_mcp\client.py`; `MCP\README.md` |
| Code execution model | Each operation sends a Painter-side Python snippet; parameters travel as base64 JSON and are exposed as `params`; the snippet assigns `result`; a lambda wrapper `exec`s it in an isolated namespace and returns `{"success": true, "data": result}` JSON | Fact | `client.py` (`execute_python_json`) |
| Errors | `PainterConnectionError`, `PainterHTTPError`, `PainterScriptError` (Painter returns `{"error": …}`) | Fact | `client.py` |
| Connection check | JS `alg.version.painter`; status also evaluates Python `substance_painter.__version__` and JS `alg.project.isOpen()` | Fact | `client.py` (`check_connection`); `OPS` (`status`) |
| Long jobs | Bake, project creation, mesh reload and shelf refresh are started inside Painter with event handlers (`event.DISPATCHER.connect_strong`) and their state is kept on Python `builtins` inside the Painter process (e.g. `builtins._sp_mcp_bake_state`, `_sp_mcp_bake_stop_source`, `_sp_mcp_project_creation_state`); polling tools read that state; only the latest job of each kind is kept | Fact | `OPS` (`get_bake_job`, `cancel_bake`, `start_batch_bake`, `create_project`) |
| Identity of layers | All layer mutations take Painter node uids (names are not unique) | Fact | `MCP\README.md` |
| Arbitrary code | `execute_python` is registered but refuses unless `SP_MCP_ALLOW_EXECUTE_PYTHON=1` | Fact | `MCP\README.md`; `SRV` |
