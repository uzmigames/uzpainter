# Tier 0 semantics goldens

Task `phase0.6_tier0-semantics-goldens` (child of `phase0.8_tier0-goldens`, D3/D13). It records the goldens that settle the open compositing questions of `docs/architecture/04-layer-stack-and-compositing.md` §9 before the kernels are frozen. Painter is observed only through its documented Python API, driven by the recorder (`RECORDER.md`). Code: `tools/parity/tier0_semantics/`. Tests: `tests/parity/test_tier0_semantics.py` (corpus, coverage, store, guard) and `tests/parity/recorder/test_tier0_vocabulary.py` (recorder vocabulary). Manifests: `parity/manifests/tier0/semantics/<golden>.json` (golden id `tier0/semantics/<golden>`). Fixtures: `parity/fixtures/tier0-semantics/`.

The schema allows one golden per public manifest, so the task's public manifest is this folder of manifests. It replaces the single file `parity/manifests/phase0/tier0-semantics.json` named in the task spec.

## 1. Corpus

Every golden is one throwaway project, built by a UzmiGames instruction sequence and exported at 16 bit (PNG) or as 32-bit float (OpenEXR, for float channel formats). A golden that compares several configurations uses a grid mesh with one texture set per configuration (`s0`, `s1`, …), so one project carries a whole sweep. Value sweeps come from authored 16-bit bitmaps rather than from one uniform colour per golden. A 256×256 field gives every pair of 8-bit lattice values, and its blue channel holds every 16-bit code once.

**Not reachable through the documented API.** The owner moved three cases to the follow-up task `phase0.7_tier0-semantics-ui-cases` (answer to q1, 2026-10-10): the height→normal method, its strength, and the `PassThrough` group mode. That task recorded them through Painter's UI under decision 029. Measured on Painter 12.1.5 (decision 047):

- The method is a per-texture-set Texture Set Settings value: `Sharp` (the default) or `Smooth (Sobel)`.
- No strength setting exists.
- The group mode is set per channel in the Layers panel. The documented `PassThrough` spelling does not exist at runtime; the getter returns `Passthrough`.

See §4.

## 3. Procedure

1. `python -m tools.parity.tier0_semantics write` regenerates the fixtures and manifests. It keeps existing `private_records` and refuses to change a manifest that already has records (goldens are immutable; a changed golden gets a new name). `check` compares the committed files with the generator, and the corpus test runs it.
2. Record each manifest under the shared Painter lock (`RECORDER.md`): `python -m tools.parity.recorder record parity/manifests/tier0/semantics/<golden>.json`. Each run holds `r1` (same session) and `r2` (after save and reopen).
3. Admit each run with `python -m tools.parity.store record <manifest> --run <inbox run>`, using the run whose record's `instruction_sequence_sha256` matches the manifest. Then run `python -m tools.parity.store verify parity/manifests/tier0/semantics`.
4. `python -m tools.parity.guard` must pass. Fits and stability are computed from the stored records by `phase0.7_tier0-stability-fits` (`parity/FITS.md`, report `parity/reports/phase0/tier0-stability.md`), and only fitted formulas are published under `parity/semantics/`.

The recorder vocabulary this corpus uses (groups, content and mask effects, levels, filters, UV projection, channel edits, effect sources) is listed in `RECORDER.md` §2.
