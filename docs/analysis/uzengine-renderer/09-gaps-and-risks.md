# 09 — Gaps and Risks: What UzEngine Lacks for a Texturing Tool

Scope: each capability a Substance-Painter-class tool needs that UzEngine does not provide today, with evidence, an effort estimate, and the natural place in the engine to add it. Effort scale: **S** (days), **M** (1-3 weeks), **L** (1-2 months), **XL** (longer). Estimates are **Recommendation/Hypothesis**-grade, not measurements. Paths relative to `E:\UzmiGames\UzEngine\`.

## 2. Risk register

| Risk | Likelihood | Impact | Evidence / mitigation |
|---|---|---|---|
| Baking only runs on DXR-capable NVIDIA/AMD/Intel GPUs on DX12 | High (by design) | Medium — CI machines must have such a GPU; no software fallback (Null backend is no-ops; WARP not confirmed) | `03-…` §6; add G6 later or document hardware requirement |
| `SceneRenderer` carries large fixed costs (GI, atmosphere, VFX subsystems initialised in `Init`) for a simple PBR preview | Medium | Medium — startup time, VRAM; CVars (`r.*`) can disable many passes (`uzengine.cpp` flushes `--cvar` before `Init`) | measure; prefer CVar-driven stripping over forking the renderer |
| ABI boundary between Zig/Clang-built `runtime.lib` and MSVC code | High if mixed | High — MSVC cannot consume Zig archives (`LNK1143`); must use the DLL + C ABI or build UzPainter entirely with Zig | `docs/engine/06-build-toolchain/04-napi-bridge.md` |
| Hidden-HWND approach breaks on headless Windows sessions without a desktop (services) | Medium | Medium | G1 true offscreen mode removes the dependency |
| `.uztexture` cannot express HDR/16-bit/cube data | Certain | Medium for emissive/height precision | G13 |
| Readback with `WaitIdle` serialises export | Certain today | Low–Medium (export is batch) | G12 |
| Normal-map convention mismatch causes inverted detail in-engine | Medium | High for a texturing tool | G15 calibration before first release |
| `uzmaterial.schema.json` misleads tooling/LLMs | Medium | Low | G21: document the real `.uzmat` and scene formats |

## 3. Reuse-first sequencing suggestion (Recommendation)

1. Stand up a window-less compute+readback skeleton exactly like `RunFlip` (`uzengine.cpp` lines 361-482): device → textures → compute PSO from generated HLSL → readback → PNG. This exercises G12 early.
2. Add G2 (UV raster) + G4 (dilation) as two small passes; validate with the pass inspector dump.
3. Add G5 baking kernels on top of `BLASManager`/RayQuery; validate AO against a reference (FLIP).
4. Build G8 compositor by extending `HlslMaterialTranslator`/`MaterialBakerGpu` to arbitrary pins and `RGBA16F`.
5. Export: etcpak + `WriteUzTexture` + `PngCodec` (16-bit) + tinyexr; emit `.uzmat`/scene material JSON per `04-…` §8.
6. Preview: hidden-HWND `SceneRenderer` with `--cvar` stripping; later G1.
7. Wrap in a C API + native MCP (G20) + optional Python (G19).
