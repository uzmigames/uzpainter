# 372. Vulkan inline ray queries behind the RHI, with a fixed TLAS binding and CPU known answers

**Status**: accepted
**Date**: 2026-11-02
**Related Tasks**: phase3.2_vulkan-ray-tracing

## Context

`phase3.2_vulkan-ray-tracing` needs acceleration structures and inline ray queries on the vendored Vulkan backend, behind the RHI calls DXR already implements (`13-engine-integration.md` §2.3, UZP-MOD-007), and a `selftest` slice that proves them on the owner's GPU. Decision 367 asks for the smallest capability-gated slice first, checked against CPU-computed answers and not only against DX12. The design went to `cx/gpt-6-astra`, `xai/grok-4.6` and `kimi/kimi-k3`, the frozen diff to `cx/gpt-6-astra`, `cx/gpt-6.1-sol` and `kimi/kimi-k3`; the machine has no Vulkan validation layer, so review covered what validation would catch.

## Decision

1. **Capability without fallback.** `vkCreateDevice` enables `VK_KHR_acceleration_structure` + `VK_KHR_deferred_host_operations` + feature `accelerationStructure` when exposed, and `VK_KHR_ray_query` + `rayQuery` on top; feature structures are queried only for exposed extensions and the five acceleration-structure entry points must resolve. `SupportsRayTracing()` means acceleration structures (no ray-tracing pipeline exists on Vulkan), `SupportsInlineRayQuery()` means both; every absent extension, feature or entry point is named (`RayQueryMissing()`). UzPainter's `render::QueryRayQuerySupport` / `RequireInlineRayQuery` (`src/render/ray_query.h`) report the same per backend (DX12: `DXR Tier 1.1`, `Shader Model 6.6`) and refuse with `gpu_backend_unavailable` before any work. The capability report gains `ray_query_missing`; on Vulkan it is the record's view checked against what the created device enabled.
2. **Binding.** With inline ray queries the one descriptor set layout gains binding 80, `ACCELERATION_STRUCTURE_KHR`, compute, partially bound and not update-after-bind (so `descriptorBindingAccelerationStructureUpdateAfterBind` is not needed, as for the storage buffers of UZP-MOD-013); a device without ray queries keeps the old layout. The ray-cast kernel (`src/render/shaders/ray_cast.hlsl`) is one HLSL file: `__spirv__` names rays, hits and TLAS at bindings 64, 65 and 80 with push constants; DX12 reads them from the descriptor heap at root-constant indices.
3. **Inputs and records.** Buffers read by builds carry the new `RHIBufferUsage::AccelerationStructureBuildInput` (Vulkan `BUILD_INPUT_READ_ONLY`, nothing on DX12). TLAS instances are packed explicitly to the 64-byte record shared by `D3D12_RAYTRACING_INSTANCE_DESC` and `VkAccelerationStructureInstanceKHR` (`PackRayInstance`), never through `RHIRTInstanceDesc`'s padded C++ layout. BLASes come from the raw RHI `CreateBLAS` with each geometry's real stride and opacity flag.
4. **Synchronization and scratch.** Each build is preceded by a barrier from every earlier command to the build stage (inputs, scratch reuse, reads of a structure rebuilt in place); `UAVBarrierAS` orders builds before every later read. Scratch is a separate buffer created with `minAccelerationStructureScratchOffsetAlignment` (128 on the RTX 4090) and its address re-checked; an override is checked for size and alignment.
5. **Refusals.** An invalid description or command is refused with its reason; a refused command records nothing and is counted, and UzPainter's Vulkan queue then submits nothing of the list. A structure counts as built for other lists only once a list holding its build was submitted (adopted from the diff review: all three reviewers found that setting it at record time let a refused list mark a structure built).
6. **Known answers.** The qualification scene (one BLAS of an opaque indexed quad with a 20-byte stride and a non-opaque quad with a 12-byte stride, three instances with a translation, a 24-bit id and a forced-opaque flag) and nine rays have hand-computed answers (`RayQueryQualificationAnswers`); the CPU reference (`RayCastReference`, double precision) must reproduce them, and the GPU records must equal both within 1e-5. Non-opaque triangles follow a kernel rule (even primitive committed, odd passed) that the reference applies, so opacity is observable. Front-face is not part of the record (the spec's record has no such field and its convention would be an unchecked assumption).
7. **Review outcomes not adopted.** Rejecting `AllowCompaction` (it permits compaction, as on DX12; nothing compacts); enabling the update-after-bind feature for the pool (the requirement concerns bindings flagged update-after-bind); dropping `SHADER_READ` at the build stage (the build-input reads are specified as `SHADER_READ` at `ACCELERATION_STRUCTURE_BUILD`). Adopted besides item 5: singular transforms and conflicting or unknown instance flags refused, at most 65535 x 64 rays per cast, non-finite record values always differ, `PackPositions` refuses strides below 12.

## Consequences

The Vulkan ray-query slice runs in `selftest` (`vulkan-ray-query-trace`) and in `uzp-render-tests vulkan-ray-query`; the same layer and kernel pass the same answers on DXR (`dx12-ray-query`). No validation layer has checked the Vulkan calls on the owner's machine. Descriptor-indexing bindless (item 2.4) and the cross-backend fixtures (2.10, 2.12) remain.
