# 157. The inferred-template-base, padding-probe and queued API-probe requests are authored from decisions 107, 111, 113, 126 and 129

**Status**: accepted
**Date**: 2026-10-12
**Related Tasks**: phase1.25_pilot-wand, phase1.18_export-engine, phase1.15_compositor-colour-fits, phase1.24_python-api-facade

## Context

Items 2.6 and 2.7 of `phase1.25_pilot-wand` wait on recordings that decisions 126 and 129 specify. So do P20-B (decision 107), P22-A and P22-C (decision 111) and P23-A (decision 113), which the existing probe vocabulary can express. Neither had a request, so the Painter session could not run them. The recording queue summarises the padding probes as a ramp probe "on seam mesh 1024+2048". Decision 129 specifies more precisely:

- P-ramp on nine meshes at 1024: ratios 1, 2 and 1.5, each at three phases, every OBJ fixed by SHA-256;
- P-tie at 512 and 2048, with its OBJ still to be fixed.

Decision 129's meshes were made by a private scratch script (`probe_gen.py`). They must be reproduced by committed code with the same bytes.

The model panel was not consulted. Decision 129 fixes the contents, and the remaining choices only follow existing patterns.

## Decision

All goldens are requested goldens under `requests/tier0/semantics/`, generated by `tools/parity/tier0_semantics/recording_requests.py` (`later_goldens()`), under Legacy.

1. **Inferred template bases (decision 126).** Three goldens, `export-template-base-<template>`, one per recorded PNG 16 code of an empty sRGB8 base:
   - `unreal-engine` (48107);
   - `openpbr-anisotropy` (59397, the OpenPBR templates);
   - `pbr-specular-glossiness` (14330, the sRGB8 Specular templates).

   Each golden is an empty project on the plane created with that template. It exports BaseColor and Specular at OpenEXR 32f, and at PNG 16 as the control against the recorded code. Painter skips a map the template lacks.
2. **P-ramp (decision 129 §4), nine goldens** `export-padding-ramp-<ratio>-<phase>`, ratio r1, r2 or r15 and phase p0, p25 or p75. Decision 129's 1024-only specification is followed, not the queue's "1024+2048" summary.
   - The meshes `seam-ramp-*.obj` are generated by `request_fixtures.ramp_seam`. Their SHA-256s equal decision 129's table, nine of nine. A test asserts them.
   - Each golden adds User0 as RGB32F. The template capture of both recordings records the stored format.
   - One fill has only User0 active. Its source is the float32 UV ramp `uv-ramp-1024.exr`: R = (x + 0.5)/N, G = (y + 0.5)/N with y counted from the top, B = 0.5. It is written as a scanline OpenEXR with ZIP compression by `request_fixtures.uv_ramp`, and decoded exactly by OpenEXR and by the test's own decoder.
   - The default projection is left as is and read back with the projection capture of decision 156. Blending is Normal at opacity 1.
   - User0 is exported at OpenEXR 32f with `infinite` padding and with `passthrough`, the covered-texel control. Each export step is done twice.
3. **P-tie (decision 129 §4), two goldens** `export-padding-tie-512` and `-2048`.
   - This decision fixes the P-tie OBJ. `tie.obj` is generated by `request_fixtures.tie`: three separate 10 cm quads, one texture set `uzp_tie`, UV squares of side 0.125 at (0.1875, 0.1875), (0.6875, 0.1875) and (0.4375, 0.6875). Its SHA-256 is the committed file's, checked by `python -m tools.parity.tier0_semantics check`.
   - The layer and exports are those of P-ramp, at document resolutions 512 and 2048, with `uv-ramp-512.exr` and `uv-ramp-2048.exr`.
4. **Queued API probes** (requests under `requests/tier0/api-probes/`, observed probe goldens like R10, `tests/parity/recorder/test_api_probes_phase1.py`):
   - `phase1-srgb-uniform-decode` is P20-B (decision 107). It sets the 256 greys c/255 and then 64 colours whose components are `random.Random(20261012).random()` in order, as sRGB uniform colours on one fill's BaseColor, each read back through `get_source`.
   - `phase1-mesh-map-update` is P22-A (decision 111).
   - `phase1-restored-values` is P22-C (decision 111). The "other edit" between the two renames is an opacity edit, restored last.
   - `phase1-save-as-existing` is P23-A (decision 113). The existing file is written by `save_as_copy`, so it is not open. The recorder lists work files by name only, so the file's size and mtime are not read. `file_path()`, `needs_saving()` and the raised error decide between overwrite and refusal.
5. **Probes, not fits.** Decision 129's limits still apply. P-ramp and P-tie are exploratory, and recording them is necessary but not sufficient for item 2.7.

## Alternatives Considered

- **An uncompressed OpenEXR, as `render_procedure.fixtures.exr_half_rgb` writes.** Rejected. Uncompressed, the 2048 px float ramp is 48 MB. With ZIP it is 0.44 MB, and all three ramps together are 0.64 MB.
- **A P-ramp at 2048 as well (the queue text).** Not authored. Decision 129 gives no targets or predictions at 2048, and a new resolution would make a new probe.

## Consequences

### Positive
- Items 2.6 and 2.7 each have committed, validated requests. The session runs 14 more Legacy goldens, and the four API probes of item 4.

### Negative
- Each P-ramp and P-tie golden is its own project, because the mesh decides the project. That makes eleven project setups for one channel each.
