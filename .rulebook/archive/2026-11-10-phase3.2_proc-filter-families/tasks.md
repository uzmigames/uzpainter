## 2. Implementation
- [x] 2.1 Discover each filter's parameter names, ranges and labels through the documented `Property` API
  - Note (2026-11-10, decision 426): `python -m tools.parity.recorder.filter_survey` (`painter_filter_survey.py`, documented symbols only) described all 62 starter filters of Painter 12.2.0 (`s:starterassets u:filter`) under the Painter lock (seq 2370); the private survey's SHA-256 is `d9c18e02…`. `python -m tools.parity.proc_filters.discovery` publishes Sharpen (`intensity` in [0, 4], default 1), Grayscale Conversion and Blur, with no description text: `docs/analysis/proc-filter-families/01-parameter-discovery.md`. The Levels filter is the native levels effect, so its fields are the documented `LevelsEffectParams` (Painter's defaults read back: the identity, clamp off). A name with a space is searched quoted (`n:"Grayscale Conversion"=`).
- [x] 2.2 Implement Sharpen and grayscale conversion as filter-effect kernels on the current layer content
  - Note (2026-10-20, decision 328 §1-§2): `src/procedural/filters.{h,cpp}`. Sharpen (`uzasset://filter/sharpen@1`) is the Laplacian sharpening of Gonzalez and Woods (4th ed., §3.6), with the content wrapping at the texture border. Grayscale conversion (`uzasset://filter/grayscale@1`) is the weighted RGB sum, with BT.709's luma weights as defaults. Each is an `IHlslFamily` with one kernel pass and a CPU reference built from the primitive library, registered from its library record (`RegisterFilterFamilies`). Both read the `content` input, which must have the output's resolution, channels and colour space (`IHlslFamily::JointRefusal`). Evidence: `tests/procedural/test_proc_filter_families.py`, case `families` (16 checks, CPU: the published formulas texel by texel, amount 0 and a constant content unchanged, tiles at the border, the joint refusal, the seam's `family not certified`); case `kernels` (DXIL and SPIR-V); case `gpu` (DX12 equal to the CPU reference bit for bit at 1024, whole and by tile, 5 parameter sets). Neither is certified. The operators come from published math only and are not calibrated yet (2.5).
- [x] 2.3 Map the Levels filter onto the native levels effect with its Tier 0 semantics
  - Note (2026-10-20, decision 328 §1): `LevelsFilterEffect` maps a `uzasset://filter/levels@1` request onto one native `core::LevelsParams` component, after the domain and joint checks. `LevelsFilterReference` is its CPU lane: `evaluator::arith::Levels` on float32 parameters, converted as the evaluator converts them, with the recording GPU's reciprocal, log2 and exp2 tables of `masks-levels.json` `levels` and `levels-clamp`. It is not an HLSL family, so the seam has no backend for it. Evidence: `tests/procedural/test_proc_filter_families.py`, case `levels` (14 checks, CPU). The defaults are the identity bit for bit, every texel equals the native arithmetic with and without clamp, and another asset, another version and a joint mismatch are refused. It is not certified as a filter asset (2.5, 3.1).
- [x] 2.4 Enforce the Filter-effect `ResolutionOverride` restriction
  - Note (2026-10-20, decision 328 §4): the python-doc says `SourceSubstance.resolution` raises `ValueError` for a source used by a `FilterEffectNode`. `src/uzp_core/types/validation.cpp` now refuses a filter effect whose `ProceduralRef` has a `resolution_override`. Every write path validates, so a transaction, `SetEffectProcedural` and a project load fail with `ValueError` and commit nothing. A generator keeps its override. The getter half of the rule belongs to the `SourceSubstance` facade, which is still a release gap (phase3.1 2.6). Its Tier 0 API probe is phase3.1 3.2.
- [x] 2.5 Calibrate black-box against private Painter oracles; write the provenance record, per-asset parity status and Tier 2a manifests; calibration starts only after item 2.6 has declared the domain and committed the held-out hash list, and never reads held-out oracles
  - Note (2026-11-10, decision 426; narrowed): Sharpen and Levels were calibrated and certified with the harness. Both are **`calibrated`, not exact**.
    - Sharpen (`tools/parity/proc_filters/sharpen_candidate.py`: the four-neighbour Laplacian on the content's 16-bit codes, written as a 16-bit code): calibration 45 of 54 exact, held-out 2 of 8. Every residual texel is one code off, at an exact code midpoint (intensity 0.25, the hat v8 recipe, and 0.63 and 2.71). Report `parity/reports/phase3/proc-cert/filter__sharpen@2/727f63f70a79abab.json`.
    - Levels (`levels_candidate.py`: the native levels effect on F(k), stored as I(I(.))): calibration 36 of 36, held-out 6 of 8. The two `interior-a` cases (gamma 1.7, output 0.05 to 0.9, no clamp) differ by up to 32 f32 ULP. Report `parity/reports/phase3/proc-cert/filter__levels@2/a278c3bef66e745b.json`.
    - Both residuals are candidate exceptions for the owner, never a pass.
    - Grayscale Conversion and Blur are not batched: no recipe uses them, and Blur's own two recordings differ.
    - No provenance record, alias or native kernel of an uncertified filter is added; the `@1` records stay `unavailable`. The four filters move to `phase3.3_procedural-families` items 2.10 to 2.12. Evidence: `docs/analysis/proc-filter-families/02-calibration-2026-11-10.md`.
- [x] 2.6 Before calibration, declare each asset's certified editable domain (parameter ranges and joint constraints, seed policy, geometry inputs, resolutions, formats and colour spaces; `05-procedural-content.md` §6, decision 222) and reserve its held-out set (meshes, interior parameter points, seeds and a resolution outside the calibration set), recorded in the same batch with its hash list committed before calibration starts; a held-out case used to change a fit is moved to the calibration set and replaced (decision 222)
  - Note (2026-10-20, decision 328 §5; not ticked): the three domains are declared before any calibration, in the shipped library (`assets/procedural/records/filter.{sharpen,grayscale,levels}@1.json`). ## 3. Tests
- [x] 3.1 Tier 2a for Sharpen, grayscale conversion and Levels on unit sphere, bevelled cube and hat v6 low × {1024, 2048, 4096} × parameter sets against private goldens, with authored input content (the calibration set), and on the held-out set reserved in 2.6, reported separately
  - Note (2026-11-10, decision 426; narrowed): Sharpen and Levels have their Tier 2a runs, with calibration and held-out reported separately in the two certification reports above (both `calibrated`). Grayscale conversion has no Tier 2a batch, because no recipe gives a parameter set; a diagnostic golden records its separating evidence. It moves with the family to `phase3.3_procedural-families` item 2.12.
- [x] 3.2 Effect-order test: a filter computes from the content produced by the effects below it and blends with its own mode and opacity
  - Note (2026-10-20, decision 328 §3): this is `FilterEffectReference`, the CPU candidate lane of `src/procedural`, not the compositor. The evaluator still refuses filter effects (`unsupported_node`) until a family is certified (phase3.3). Evidence: `tests/procedural/test_proc_filter_families.py`, case `effect-order` (8 checks). A grayscale filter above a fill effect reads the content after the fill and blends with Normal 0.75 and Multiply 1 through the effect mix; the reverse order gives another result. A content other than the one the request names by SHA-256 is refused, and so is a mode without a kernel. A Levels filter blends the same way. The filter effect's mix is the fill effects' Tier 0 effect mix; no golden records a filter's own mix yet (3.4).
- [x] 3.3 `ResolutionOverride` on a filter-used source raises as documented
  - Note (2026-10-20): `tests/procedural/test_proc_filter_families.py`, case `resolution-override` (8 checks, CPU). A transaction that sets an override on a filter effect's source fails with `ValueError` and leaves the revision and the project unchanged. A generator's source accepts one. A stored project with one fails validation. `SetEffectProcedural` with an admitted filter reference that carries one fails in its transaction; the same reference without it is accepted.
- [x] 3.4 Tier 0 `effect-order` s0–s5, s7 exact (content-effect order of fill and levels effects around Blur; phase1.11_compositor-mask-effects item 3.3)
  - Note (2026-10-21, decision 346): exact on the CPU and on DX12 against both recordings, RGB16 and sRGB8 (`tests/evaluator/test_compositor_mask_effects.py::test_content_effect_order_equals_the_golden`, 14 cases; `masks-levels.json` `content-effect-order` now `exact`). Two findings.
    - The content fill effect used the mask effect mix `fl(a + fl(fl(r - a) alpha))`, which left one 16-bit code off on up to 32 values per set. It now takes the layer mix `fl(fl(a fl(1 - alpha)) + fl(r alpha))`. Masks keep the effect mix.
    - At its recorded configuration the starter Blur is the content rounded toward zero to binary16: default parameters, Normal 1, RGB16 or sRGB8, 256 x 256, legacy colour management. The s7 borders bound any kernel weight below 0.002. This is not a Blur implementation. Every other parameter, blending, format, resolution and filter fails with `unsupported_node` (`test_blur_outside_the_recording_is_refused`). The family is uncertified, and no alias or asset record names it.
    - Items 2.1, 2.5 and 2.6 still own the real Blur.
- [x] 3.5 Domain-refusal test: a parameter, seed, mesh-map input and resolution just outside the declared domain each raise `UnsupportedProcedural{reason: "outside certified domain"}` before mutation, with nothing clamped or substituted
  - Note (2026-10-20, decision 328 §2, §5): `tests/procedural/test_proc_filter_families.py`, case `domain` (CPU). Eleven requests just outside a declared domain go through `SetEffectProcedural` on a filter effect. Each raises `UnsupportedProcedural{reason: "outside certified domain"}` that names the field and the exact requested value (nothing is clamped), and no transaction opens. They are: a Sharpen amount one ulp above its range and one ulp below it, a grayscale weight one ulp above, seed 1 against the listed seed 0, an undeclared mesh-map input (filters read content, not mesh maps), a content input in another format, a content at another resolution than the output, output resolutions 512 and 8192, another mesh class, and a missing content. The candidate lane evaluates none of them. Inside the domain the uncertified Sharpen is still refused (`family not certified`). The Levels filter refuses through `LevelsFilterEffect`: gamma one ulp above its range, its joint constraint, a clamp outside its set, seed 1 and resolution 512. The edit has no backend for it at all.
