Tasks `phase1.5_compositor-tile-dag`, `phase1.8_compositor-sources-projection`, `phase1.9_compositor-quantisation-profile`, `phase1.10_compositor-blend-kernels` and `phase1.11_compositor-mask-effects` (children of `phase1.14_compositor-core`, P1-COMPOSITOR). Implements `docs/architecture/04-layer-stack-and-compositing.md` §1 (fill sources, masks and effects), §2 (steps 1–7; anchors excluded), §3 (blend modes), §4 (the evaluator profile, the storage rules the kernels share, colour transfer, sampling), §5 (the `Fill` and `UV` projections) and §7 (DAG, cache, admission, generated kernels), and the project templates of `03-project-model.md` §2. Tests: `tests/evaluator/` (`zig build evaluator-tests`, `python -m pytest tests/evaluator`). Local run reports: `parity/reports/phase1/compositor-tile-dag.md`, `parity/reports/phase1/compositor-sources-projection.md`, `parity/reports/phase1/compositor-quantisation-profile.md`, `parity/reports/phase1/compositor-blend-kernels.md`. ## 1. Shape

| File | Role |
|---|---|
| `arith.{h,cpp}` | The scalar rules every backend shares: UNORM operand tables (`float32(code / M)`), the sRGB8 operand and store (the recording GPU's sRGB8 decode and float-to-sRGB8 thresholds, measured by `uzp-evaluator-tests srgb8-hardware`; thresholds compared in double), the UNORM write rule (truncate to n + 4 fractional bits, nearest, ties down), the 16-bit float store toward zero, the raw 32-bit float store and the 32-bit float read-out `base + (v - base)`, the blend kernels of every mode (`parity/semantics/blend-kernels.json`: the separable kernels per channel, the component and normal-map kernels per texel) and the per-texel composite. |
| `hwmath.{h,cpp}`, `tables/hw-*.zlib` | The recording GPU's float32 reciprocal, square root and reciprocal square root (RTX 4090, D3D12): the correctly rounded result moved by a measured -2..+1 ulp per mantissa, from zlib-compressed 2-bit tables embedded at build time (`uzp-evaluator-tests fp-hardware` measures them and checks them against the GPU). Its base-2 logarithm and exponential (`hw-lg2-hi`, `hw-lg2-lo`, `hw-ex2-pos`, `hw-ex2-neg`: the measured results over 2^23 mantissas each, stored as zlib second differences, 128 MiB once inflated; the rest of the domain follows by rule) and pow(x, g) = exp2(g log2 x), which is exactly the GPU's pow (`uzp-evaluator-tests pow-hardware` measures the tables and checks log2, exp2 and pow on edge values and 2^20 hashed inputs). Used by the kernels where Painter divides, takes roots or raises to a power; the CPU and every GPU read the same tables. |
| `profile.{h,cpp}` | Evaluator profiles: the registry (`FindProfile`, `RegisterProfile`), `painter-12.1-layerq-linear` (provisional, root over the base) and `painter-12.1-isolated-linear` (settled, current: isolated root composited over the base at read-out). A project is evaluated with the profile it records (`versions.evaluator_profile`); an unregistered id fails with `evaluator:unknown_profile`; a registered id never changes meaning. |
| `formats.h` | `TileFormat` (encoding, 1 or 3 channels, sRGB flag, coverage plane), its GPU format and byte cost; the 1024-texel tile grid. |
| `templates.{h,cpp}` | `TemplateLibrary`: `assets/templates/*.json` (§3). |
| `hash.{h,cpp}` | SHA-256 `HashWriter` for subtree hashes. |
| `dag.{h,cpp}` | `BuildDag`: the per-(set, stack, channel) evaluation DAG from a snapshot, with the subtree hash of every node output (§2). |
| `admission.{h,cpp}` | `AdmissionLimits` from the render layer's budget, `CheckTextureSet` (refusal at creation), `TileCache` (LRU under the limits, pins). |
| `tile_store.h` | `ITileStore`: allocate, upload, project, blend (with the effect mix), levels, flush, read. |
| `cpu_store.{h,cpp}` | The CPU store: the reference, and the path without a GPU. |
| `kernelgen.{h,cpp}`, `shaders/evaluator_blend.hlsl` | One generated kernel per (blend mode, tile format), compiled through the render layer's kernel cache, the effect mix a runtime flag; one Levels kernel per tile format (`UZP_LEVELS`); parameter blocks in an arena buffer; one operand-tables buffer (16-bit UNORM operands and the hardware arithmetic tables, `OperandTableWords`) and, on first use of a gamma, the log2/exp2 tables buffer (`kPowWords`, 128 MiB). |
| `gpu_store.{h,cpp}` | The GPU store on the engine thread: textures, batched blend and projection dispatches in queue order, the VRAM cache of packed bitmap codes keyed by (hash, encoding), `TextureReadback`. |
| `sources.{h,cpp}` | Colour rules of fill sources, `CheckColourManagement` (legacy only), `DecodeBitmap` (8/16-bit PNG through spng) and `DecodingResourceProvider` (bytes checked against their SHA-256, decoded once, RAM cache by hash). |
| `projection_uv.{h,cpp}`, `shaders/evaluator_project.hlsl` | The `Fill` and `UV` projections: transform, `Nearest`/`BilinearHQ`/`BilinearSharp`, the four wrap modes, the Height range; the CPU reference and the kernel (one per tile format). |
| `evaluate.{h,cpp}` | Running a DAG tile by tile on a store under the cache: layer lists, content-effect and mask-effect chains (each from its highest cached output), effects on constants folded on the CPU with the same arithmetic. |
| `geometry_mask.{h,cpp}` | `Mesh` geometry masks: `IGeometryMaskProvider` (the set raster of an inclusion or exclusion list) and `MeshGeometryMasks`, the texel-centre coverage of the texture set's triangles of the included objects (the UV raster's convention). |
| `evaluator.{h,cpp}` | `Evaluator` (engine thread, GPU) and `CpuEvaluator`; `EvaluateOn` is their shared body. |
| `error.{h,cpp}` | Evaluator failures as `render::Error` with the reason `evaluator:<kind>[ node=<uid>]: <detail>`. |

Everything runs on revision snapshots (`core::Snapshot`); the GPU path submits one engine request per channel evaluation and keeps the cache across requests.

## 2. Semantics implemented (and their evidence)

- **Profile, base value, bottom-up order** (`phase1.9`, `phase1.10`, `parity/semantics/quantisation-profile.json`). Root layers are walked bottom-up; each contributing layer blends with its per-channel mode and opacity and the result is written to the channel format after every layer. Under the profiles `painter-12.1-isolated-linear` and the current `painter-12.1-isolated-half-alpha` the root list is isolated like a group: it composites from a transparent start (coverage in a fourth plane, stored in the channel format) and the result is composited over the template's base once per tile, `v = base + (C - base) a` (the `Replace` mix at opacity 1, a cached `Readout` tile), then written with the channel's write rule. This reproduces the same-session recording of the Tier 0 quantisation experiment (three 1/3-opacity fills on every ChannelFormat member) on every UNORM, sRGB8 and 16-bit float map, and every map of `blend-inputs` s2 (one layer at 0.5 over the base, where the stored coverage sends exact ties up); 5 of the 16 32-bit float values of the experiment are 2^-25 or 2^-24 off under the current profile (6 under `isolated-linear`; a divergence, `parity/reports/phase1/compositor-float32-residual.md`). Both goldens are unstable (r2 differs from r1): under decision 032 r1 is their exact target and `EXC-001`/`EXC-002` cover r2. `painter-12.1-isolated-half-alpha` (decision 044) differs from `isolated-linear` in two write rules only: the coverage plane of an sRGB8 intermediate is written as the 8-bit code of its binary16 value (`arith::HalfNearestEven`, `TileFormat::halfCoverage`; `group-masks` s2-s3 sRGB8 exact, a coverage half-way between two codes goes up or down as its binary16 value lies), and a uniform colour on a 32-bit float channel is its float32 value. The provisional `painter-12.1-layerq-linear` (accumulator starting at the base) and `painter-12.1-isolated-linear` stay registered for projects stamped with them and evaluate as before. Evidence of the order: `blend-order` RGB16 maps exact on both recordings (`tests/evaluator/test_compositor_tile_dag.py::test_evaluation_order_equals_the_golden`).
- **An empty channel is its base constant**, not a stored code: Painter's empty channels export values no channel code produces (the BaseColor of the shipped templates, `float32(127/255)` on an RGB16F Normal). The evaluator returns the constant; an exporter writes it with the float write rule of the export depth (16-bit PNG: the UNORM write rule; OpenEXR: the float32). Evidence: every `base-values-*` golden exact.
- **Groups.** A group composites its visible children from a transparent start into an isolated intermediate (coverage in a fourth plane, quantised to the channel format after each child), then blends that intermediate with its own mode and opacity. Painter's default group mode behaves exactly so: in `group-masks` the default-mode group (s0) and the `Normal` group (s1) are identical texel for texel, and both are reproduced exactly on RGB16 and RGB32F. `PassThrough` (documented, not settable through Painter 12.1.0's API, `phase0.7_tier0-semantics-ui-cases`) composites the children directly into the stack with their opacities scaled by the group's: a hypothesis until recorded. `Disable` skips the node for that channel.
- **32-bit float channels.** Accumulators stay raw; the `1 + (v - 1)` of `blend-modes.json` (the channel re-composited over its base) is the read-out composite at full coverage: the isolated root's read-out blend applies it (`painter-12.1-layerq-linear`: `arith::Float32Readout` once at read-out, `evaluate.cpp`), as the blend fits read their backdrop raw; under the earlier profiles a uniform colour on such a channel reads back through it (the fit's `uniform_operand`), under `isolated-half-alpha` it is its float32 value (`group-masks` row 0: the read-out operand leaves 8 values off). Evidence: `group-masks` RGB32F exact with raw accumulators, 1 ulp off in 12 693 texels when applied per layer; `blend-inputs` s2 RGB32F exact with `base + (C - base) a` (the mix `base (1 - a) + C a` differs on 10 922 values).
- **Isolated composite.** W3C Compositing and Blending Level 1 §5.1 with straight colours: an opaque backdrop gives the fitted mix `a (1 - alpha) + r alpha` (`Replace`: `a + (r - a) alpha`), a transparent backdrop passes the source through, a partly covered backdrop uses the general formula in float32 with a correctly rounded reciprocal (`group-masks` s2-s3 and `quantisation-thirds`: within one export step of Painter on 32-bit float and RGB16 channels, the order of Painter's float32 operations not identified).
- **Instances** evaluate their source layer in their own position; **invisible** layers are skipped; an **empty mask** is its background (White 1, Black 0); a disabled mask is 1.
- **Masks** (`phase1.11`, `parity/semantics/masks-levels.json`). A layer's or group's mask is mono and independent of the channel (one raster, cached once, for every channel of the layer). It starts from its background and runs its visible effects bottom-up: a fill effect blends its mono source (a uniform colour's mean, or a bitmap's first component, projected like any fill) with its own mode and opacity through the **effect mix** `v = a + (r - a) alpha` for every mode (the layer mix `a (1 - alpha) + r alpha` misses 6 of 65 536 texels of `mask-precision` s3), `r` the mode's kernel clamped to [0, 1], so subtraction is the `Subtract` kernel; a levels effect remaps the mask (Painter's API gives it no blending). The mask is stored at **16 bits** after every effect on every channel format (`mask-precision`: RGB16, L16, RGB32F, sRGB8 and L8 exact on both recordings; an 8-bit mask misses thousands of texels). A `Mesh` geometry mask multiplies the mask (its raster from `IGeometryMaskProvider`); `UVTile` geometry masks fail. The layer blends with opacity × mask. A group's mask scales its isolated composite as a layer's does (`group-masks` s2-s3: exact where the child's mask is 0 or 1).
- **Content effects** (`phase1.11`). A fill layer's content runs through its visible content effects in list order, stored in the channel format after each: a fill effect blends its source for the channel (when active on it) with its per-channel mode and opacity through the effect mix; a levels effect remaps its affected channel only. **Levels** (arith::Levels): `t = (v - in_min) Rcp(in_max - in_min)` with the hardware reciprocal; `clamp` limits t to [0, 1] (the output range is never clamped); a gamma other than 1 gives `sign(t) pow(|t|, gamma)` through the hardware pow; `out = fma(t, out_max - out_min, out_min)`. Exact: `levels-clamp` (16 maps, both recordings), `effect-order` s6 (RGB16 and sRGB8). The order of fill and levels effects is the documented list order; every Tier 0 order but s6 and s7 holds the Blur filter (P3-PROC), so it is not yet observed.
- **Height override** (LAY-03). `EffectiveBlending(layer, channel)` reads the blending that applies to a node on a channel: its own entry or Normal at 1; a group's `Height` entry is the blending of its composite on Height (the per-group override), its children keep theirs.
- **Cache shape** (planning review: settled before mask effects depend on it). Content and mask effect chains are nodes keyed by chained hashes (`CacheKind::Effect`, `CacheKind::Mask`); a layer's contribution hash covers its final content and mask hashes. An upstream change (a mask or content effect, as an anchor's would be) re-evaluates only its chain from the change up and the prefixes above the layer; the masks of a layer are shared by its channels (`uzp-evaluator-tests masks`).
- **Sources** (`phase1.8`, `parity/semantics/colour-transfer.json`). Uniform colours are taken as linear and stored like a channel value, then read back (`blend-modes.json` `uniform_operand`; a grey channel takes the mean of the three components); sRGB, Working and Raw give the same codes under legacy colour management. sRGB8 channels store through the recording GPU's float-to-sRGB8 conversion and read through its decode (not the IEC rounding: 2 936 of 65 536 operands differ), which makes the uniform ramps, the sRGB8 export and every sRGB8 stack golden exact. Bitmaps are bound by content hash (LAY-13: the alias plays no part), decoded once, and a code `c` is the linear value `float32(c / M)` stored with the channel's write rule (exact on RGB16, sRGB8, RGB8, L16: `blend-inputs`); on the Height channel the value is `2 t - 1` over the signed channel's base 0 (`height-normal-plane-amplitudes` s0-s3 exact; the templates' Height base is 0 and its 16-bit PNG export is `(h + 1) / 2`). OCIO colour management fails with `unsupported_source`.
- **Projections** (`phase1.8`, `parity/semantics/uv-sampling.json`). `Fill` is the identity with `Repeat`; `UV` applies the documented transform about the UV centre in double, `Nearest` (exact at every scale) and the bilinear filters as the recording GPU's linear filter of a float32 texture, measured at every 8-bit weight pair (`BilinearFilter`: 8-bit weights, operands with 28 bits below the largest weighed texel's exponent, one rounding, ties up; `resample-uv` magnification and 1:1 exact under every filter and wrap mode, `phase1.9_compositor-resample-gaps`). A wrap mode that can leave texels uncovered gives the content tile a coverage plane, so the fill keeps the value below there. Bilinear minification, physical-size scale modes and non-power-of-two sets fail with `unsupported_source`. Island edges: the evaluator fills the whole UV tile; on every texel-centre-covered texel of the imported mesh's UV raster it equals the goldens (sphere, bevelled cube), and texels outside the islands are export padding.
- **Kernels** (`phase1.10`, `parity/semantics/blend-kernels.json`). Every documented `BlendingMode` but `PassThrough` (a group placement) has a kernel, per channel with per-channel opacity. The 24 separable modes (Normal, Replace, Disable, Multiply … PinLight) equal the Tier 0 sweeps exactly on every format (RGB16 at opacity 1 and 0.5, sRGB8 at 1 and 0.5, RGB8, RGB16F, L16, RGB32F at 0.25) against both recordings. Two facts made them exact: Painter divides and takes square roots with the GPU's faithful (not correctly rounded) float32 instructions, reproduced from the measured tables of `hwmath.h` (Divide, InverseDivide, ColorBurn, ColorDodge, VividLight: reciprocal; SoftLight: square root), and ColorBurn's opacity mix is one rounding, `fma(a, 1 - alpha, r alpha)`. Explicit fused multiply-adds (the float32 rounding of the exact `x y + z`) only where the goldens show them: Exclusion, Screen, HardLight and Overlay (upper branch), SoftLight, ColorBurn (kernel and mix) and the normal-map dot products and reoriented mapping; contraction stays off everywhere else. The normal-map modes (`phase1.11`, decision 046) decode, rotate the upper normal toward (0, 0, 1) by the opacity, combine (whiteout, reoriented normal mapping with `r.z = t.z (d - u.z)`) and normalise through the hardware reciprocal square root. The rotation is n' = (n.x k, n.y k, cos(a t)), with t = pi/2 - asin(z) and k = sin(a t) rsqrt(fma(-z, z, 1)). Its sine and cosine come from tables measured on the recording GPU (`hw::Sin`, `hw::Cos`, `trig-hardware`), and its arcsine is the GPU's GLSL `asin` polynomial (`hw::Asin`). These modes are exact at every recorded opacity, on every format and on the Normal channel. The component modes (Tint, Saturation, Color, Value) follow the fitted hue of `phase1.11` (`arith.cpp Hue`): exact on grey and sRGB8 channels, within one code elsewhere. They stay release gaps (`blend-kernels.json`; no exception). Correctly rounded reciprocal and square root (the hardware result corrected with exact double residuals on the GPU) remain for the compositing arithmetic; IEEE minNum/maxNum where the fit uses numpy `fmin/fmax`, NaN propagation where it uses `minimum/maximum`. GPU = CPU bit for bit for every mode (`kernel-sweep`, `gpu-vs-cpu`).
- **Cache.** Every subtree hash is seeded with the project's profile id (tiles of two profiles never serve each other), channel, format and the set resolution, so a resized set never reuses a tile of the old size. Node outputs are tiles keyed by `(node, kind, subtree hash, tile)`: `Content` for a layer's bitmap tile, `Prefix` for the accumulator of a layer list after a layer (chained hashes from the list start, which includes profile, channel, format and base). An isolated root adds a `Readout` tile (the root composited over the base), looked up first. A list is evaluated from its highest cached prefix upward, so an edit re-evaluates only the layers above it; untouched channels and tiles are served whole. Subtree hashes cover only evaluation-relevant fields (names and UI state do not invalidate).
- **Admission.** Limits come from `render::AdmissionBudget` (13 §6). `CheckTextureSet` admits a set when its final tiles plus a three-tile working set fit; `TileCache::Allocate` evicts least recently used unpinned tiles and fails explicitly (`tile_budget_exceeded`) when pinned tiles leave no room; the evaluator flushes queued GPU work and releases finished inputs before failing.

## 3. Templates (`assets/templates/`)

One JSON per shipped Painter 12.1.0 template (26), `default.json` for the project created with no template, and `channel-defaults.json` for channels added afterwards. Schema `uzpainter/template/1`: `id`, `name`, `kind` (`project` | `channel-defaults`), `painter_template` (the shelf path the template reproduces), `provenance` (channel set: the `project-templates` capture; base values: the `base-values-<template>` golden; record hashes), `channels[]` with `type` (`ChannelType`), `format` (`ChannelFormat`, project templates only), `base` (three float32 components) and `base_provenance`:

- `observed`: the private golden, its record hash, the map and the 16-bit export codes the base reproduces (the base is the nearest float32 to `code / 65535`, checked to write back to the code; the signed Height channel exports `(h + 1) / 2`, so its observed code 32767 is the base 0);
- `fitted`: a published fit (`height-to-normal.json` flat normal, `ao-mixed.json` white AO);
- `unobserved`: no document map exports the channel (coat, fuzz, subsurface weight/colour, tangent); authored by analogy and listed as such in the local run report. A channel type absent from both a template and the defaults fails evaluation with `missing_base_value`.

Authored by UzmiGames; never generated from a capture (the goldens are compared with the files in the local run, `test_template_channel_sets_equal_the_capture`, `test_base_values_equal_the_empty_project_exports`). `TemplateLibrary::DefaultDirectory()` is `assets/templates` beside the executable (installed by `zig build painter` and `evaluator-tests`).

## 4. Out of this profile (explicit failures, capability gaps)

Paint layers and effects, generator and filter effects (P3-PROC), compare-mask, colour-selection and anchor effects (P4-NODES), `UVTile` geometry masks, a `PassThrough` group with a mask raster, `Material` source mode, procedural/vector/font/reference sources, 3D projections and symmetry, physical-size UV scale modes, bilinear minification, OCIO colour management. Implemented but not exact against a golden: the float32 source-over onto a partly covered backdrop on 32-bit float and RGB16 channels (`group-masks` s2-s3: 57 RGB16 and 20 631 RGB32F values of 196 608 off by one step; `quantisation-thirds`: 5 of 16 float values; a divergence after `phase1.10_compositor-float32-residual`'s search, decision 044, the exception the owner's decision); the RGB8/L8 coverage rule at an 8-bit tie (no golden; plain 8-bit write kept). Implemented but not exact (release gaps of `blend-kernels.json`, evaluated without failing): the component blend modes on colour channels and the normal-map modes below opacity 1. Unobserved and implemented by analogy: uniform colours on Height (no remap), 8-bit and sRGB-tagged bitmaps, `RepeatHorizontally`/`RepeatVertically`. Each fails before any work with `evaluator:unsupported_*` naming the node and the task that owns it.
