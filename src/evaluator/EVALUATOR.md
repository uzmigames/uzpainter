## 1. Shape

| File | Role |
|---|---|
| `arith.{h,cpp}` | The scalar rules every backend shares: UNORM operand tables (`float32(code / M)`), the sRGB8 operand and store (the recording GPU's sRGB8 decode and float-to-sRGB8 thresholds, measured by `uzp-evaluator-tests srgb8-hardware`; thresholds compared in double), the UNORM write rule (truncate to n + 4 fractional bits, nearest, ties down), the 16-bit float store toward zero, the raw 32-bit float store and the 32-bit float read-out `base + (v - base)`, the blend kernels of every mode (`parity/semantics/blend-kernels.json`: the separable kernels per channel, the component and normal-map kernels per texel) and the per-texel composite. |
| `hwmath.{h,cpp}`, `tables/hw-*.zlib` | The recording GPU's float32 reciprocal, square root and reciprocal square root (RTX 4090, D3D12): the correctly rounded result moved by a measured -2..+1 ulp per mantissa, from zlib-compressed 2-bit tables embedded at build time (`uzp-evaluator-tests fp-hardware` measures them and checks them against the GPU). Its base-2 logarithm and exponential (`hw-lg2-hi`, `hw-lg2-lo`, `hw-ex2-pos`, `hw-ex2-neg`: the measured results over 2^23 mantissas each, stored as zlib second differences, 128 MiB once inflated; the rest of the domain follows by rule) and pow(x, g) = exp2(g log2 x), which is exactly the GPU's pow (`uzp-evaluator-tests pow-hardware` measures the tables and checks log2 and exp2 on 2^20 inputs each, 40 edge values and 1 048 536 hashed ones, and pow on 2^20 hashed inputs). Used by the kernels where Painter divides, takes roots or raises to a power; the CPU and every GPU read the same tables. |
| `profile.{h,cpp}` | Evaluator profiles: the registry (`FindProfile`, `RegisterProfile`), `painter-12.1-layerq-linear` (provisional, root over the base) and `painter-12.1-isolated-linear` (settled, current: isolated root composited over the base at read-out). A project is evaluated with the profile it records (`versions.evaluator_profile`); an unregistered id fails with `evaluator:unknown_profile`; a registered id never changes meaning. |
| `formats.h` | `TileFormat` (encoding, 1 or 3 channels, sRGB flag, coverage plane), its GPU format and byte cost; the 1024-texel tile grid. |
| `templates.{h,cpp}` | `TemplateLibrary`: `assets/templates/*.json` (§3). |
| `hash.{h,cpp}` | SHA-256 `HashWriter` for subtree hashes. |
| `dag.{h,cpp}` | `BuildDag`: the per-(set, stack, channel) evaluation DAG from a snapshot, with the subtree hash of every node output (§2). |
| `admission.{h,cpp}` | `AdmissionLimits` from the render layer's budget, `CheckTextureSet` (refusal at creation), `TileCache` (LRU under the limits, pins). |
| `tile_store.h` | `ITileStore`: allocate, upload, project, blend (with the effect mix), levels, flush, read. |
| `cpu_store.{h,cpp}` | The CPU store: the reference, and the path without a GPU. |
| `kernelgen.{h,cpp}`, `shaders/evaluator_blend.hlsl` | One generated kernel per (blend mode, tile format), compiled through the render layer's kernel cache, the effect mix a runtime flag; one Levels kernel per tile format (`UZP_LEVELS`); parameter blocks in an arena buffer; one operand-tables buffer (16-bit UNORM operands and the hardware arithmetic tables, `OperandTableWords`) and, on first use of a gamma, the log2/exp2 tables buffer (`kPowWords`, 128 MiB). |
| `gpu_store.{h,cpp}` | The GPU store on the engine thread: textures, batched blend and projection dispatches in queue order, the VRAM cache of packed bitmap codes keyed by (hash, encoding), `TextureReadback`. |
| `sources.{h,cpp}` | Colour rules of fill sources, `CheckColourManagement` (legacy only), `DecodeBitmap` (8/16-bit PNG through spng) and `DecodingResourceProvider` (bytes checked against their SHA-256, decoded once, RAM cache by hash). |
| `projection_uv.{h,cpp}`, `shaders/evaluator_project.hlsl` | The `Fill` and `UV` projections: transform, `Nearest`/`BilinearHQ`/`BilinearSharp`, the four wrap modes, the Height range; the CPU reference and the kernel (one per tile format). |
| `evaluate.{h,cpp}` | Running a DAG tile by tile on a store under the cache: layer lists, content-effect and mask-effect chains (each from its highest cached output), effects on constants folded on the CPU with the same arithmetic. |
| `geometry_mask.{h,cpp}` | `Mesh` geometry masks: `IGeometryMaskProvider` (the set raster of an inclusion or exclusion list) and `MeshGeometryMasks`, the texel-centre coverage of the texture set's triangles of the included objects (the UV raster's convention). |
| `height_to_normal.{h,cpp}` | The virtual normal maps `Normal_OpenGL`/`Normal_DirectX` and the geometry-only pass-through (§2, Height and normals): the stencils, the combination of one texel (shared with the `UZP_VNORMAL` kernel of `shaders/evaluator_blend.hlsl`), the orchestration over the Height and Normal read-outs (`EvaluateVirtualNormalOn`) and the EXP-09 `NormalTag`. |
| `diagnostics.{h,cpp}` | The diagnostics (§2, Diagnostics): `IsolateOn`, `ContributionOn`, `MaterialViewsOn`, `ComputeRegionStats`, the export plan's `diagnosticMap` sources (`SourceName`, `ParseSourceName`, `EvaluateDiagnosticOn`). |
| `evaluator.{h,cpp}` | `Evaluator` (engine thread, GPU) and `CpuEvaluator`; `EvaluateOn`, `EvaluateVirtualNormalOn` and `EvaluateDiagnosticOn` are their shared bodies (`Evaluate`, `EvaluateNormal`, `Diagnose`, `EvaluateMaterialViews`). |
| `error.{h,cpp}` | Evaluator failures as `render::Error` with the reason `evaluator:<kind>[ node=<uid>]: <detail>`; `ErrorClassName`, the API class of each kind (decision 082): `unsupported_*` are `NotYetSupported`, `invalid_argument` (a malformed diagnostic argument) and `not_found` `ValueError`. |
| `support.{h,cpp}` | The Phase 1 support boundary as a check before mutation (`phase1.14_compositor-core`, decisions 081, 082): `RequireSupported(before, after)` throws `core::NotYetSupported` naming the node, the feature and its owner task for the first release gap a request adds or changes (the `release-gap` entries of `tools/capabilities/compositor-capabilities.json`). |

Everything runs on revision snapshots (`core::Snapshot`); the GPU path submits one engine request per channel evaluation and keeps the cache across requests.

## 2. Semantics implemented (and their evidence)

- **Profile, base value, bottom-up order** (`phase1.9`, `phase1.10`, `parity/semantics/quantisation-profile.json`). Root layers are walked bottom-up; each contributing layer blends with its per-channel mode and opacity and the result is written to the channel format after every layer. Under the profiles `painter-12.1-isolated-linear`, `painter-12.1-isolated-half-alpha` and the current `painter-12.1-isolated-coverage-weights` the root list is isolated like a group: it composites from a transparent start (coverage in a fourth plane, stored in the channel format) and the result is composited over the template's base once per tile, `v = base + (C - base) a` (the `Replace` mix at opacity 1, a cached `Readout` tile; one fused `fma(C - base, a, base)` under `isolated-coverage-weights`), then written with the channel's write rule. Under the current profile this reproduces the same-session recording of the Tier 0 quantisation experiment (three 1/3-opacity fills on every ChannelFormat member) on every map, the 32-bit float maps included, and every map of `blend-inputs` s2 (one layer at 0.5 over the base, where the stored coverage sends exact ties up); the earlier isolated profiles leave 5 (`isolated-half-alpha`) and 6 (`isolated-linear`) of the 16 32-bit float values 2^-25 or 2^-24 off (`parity/reports/phase1/compositor-float32-residual.md`). Both goldens are unstable (r2 differs from r1): under decision 032 r1 is their exact target and `EXC-001`/`EXC-002` cover r2. `painter-12.1-isolated-half-alpha` (decision 044) differs from `isolated-linear` in two write rules only: the coverage plane of an sRGB8 intermediate is written as the 8-bit code of its binary16 value (`arith::HalfNearestEven`, `TileFormat::halfCoverage`; `group-masks` s2-s3 sRGB8 exact, a coverage half-way between two codes goes up or down as its binary16 value lies), and a uniform colour on a 32-bit float channel is its float32 value. `painter-12.1-isolated-coverage-weights` (decisions 058, 059) adds the coverage-weighted source-over (below), the fused read-out, the grey of a uniform colour as the float32 of the mean of its unrounded components (`quantisation-thirds` L32F) and the binary16 sRGB8 coverage from 1/2 up only (`TileFormat::halfCoverageFromHalf`; `group-coverage-order` s3: eight ties below 1/2 go down). The provisional `painter-12.1-layerq-linear` (accumulator starting at the base), `painter-12.1-isolated-linear` and `painter-12.1-isolated-half-alpha` stay registered for projects stamped with them and evaluate as before. Evidence of the order: `blend-order` RGB16 maps exact on both recordings (`tests/evaluator/test_compositor_tile_dag.py::test_evaluation_order_equals_the_golden`).
- **An empty channel is its base constant**, not a stored code: Painter's empty channels export values no channel code produces (the BaseColor of the shipped templates, `float32(127/255)` on an RGB16F Normal). The evaluator returns the constant; an exporter writes it with the float write rule of the export depth (16-bit PNG: the UNORM write rule; OpenEXR: the float32). Evidence: every `base-values-*` golden exact.
- **Groups.** A group composites its visible children from a transparent start into an isolated intermediate (coverage in a fourth plane, quantised to the channel format after each child), then blends that intermediate with its own mode and opacity. Painter's default group mode behaves exactly so: in `group-masks` the default-mode group (s0) and the `Normal` group (s1) are identical texel for texel, and both are reproduced exactly on RGB16 and RGB32F. `PassThrough` (`phase1.11`; set through Painter's UI, the runtime member is `Passthrough`) composites the children onto a copy of the accumulator below the group, each stored in the channel format with its own mode, opacity and mask; its first child is over the empty start only where the group is the first layer of a list that starts empty, so under `isolated-coverage-weights` a child over a backdrop that is not opaque takes the coverage weights like any layer (decision 066). The accumulator then moves toward that result by the group's opacity and mask, `fma(g - a, t, a)` over an opaque backdrop. This is exact against `semantics-ui/group-passthrough-masks` (no mask, group mask, child mask, both) under the current profile. That golden's backdrop (fields A) is opaque: a PassThrough over a backdrop that is not opaque (its children's coverage weights, and its mix: the result with coverage t times its coverage over a transparent backdrop, the premultiplied lerp with a correctly rounded reciprocal between, under every profile) is not recorded. `Disable` skips the node for that channel.
- **32-bit float channels.** Accumulators stay raw; the `1 + (v - 1)` of `blend-modes.json` (the channel re-composited over its base) is the read-out composite at full coverage: the isolated root's read-out blend applies it (`painter-12.1-layerq-linear`: `arith::Float32Readout` once at read-out, `evaluate.cpp`), as the blend fits read their backdrop raw; under the earlier profiles a uniform colour on such a channel reads back through it (the fit's `uniform_operand`), from `isolated-half-alpha` on it is its float32 value (`group-masks` row 0: the read-out operand leaves 8 values off). Evidence: `group-masks` RGB32F exact with raw accumulators, 1 ulp off in 12 693 texels when applied per layer; `blend-inputs` s2 RGB32F exact with `base + (C - base) a` (the mix `base (1 - a) + C a` differs on 10 922 values).
- **Isolated composite.** W3C Compositing and Blending Level 1 §5.1 with straight colours: an opaque backdrop gives the fitted mix `a (1 - alpha) + r alpha` (`Replace`: `a + (r - a) alpha`). Under `painter-12.1-isolated-coverage-weights` (decision 058) every other backdrop but the empty start of a list, a backdrop layer of coverage 0 included, takes the coverage weights: `wb = fl(ab fl(1 - as))`, `ao = fl(as + wb)`, `ws = fl(ao - ab)`, `C = fl(fma(ws, Cs, fma(ab, fl(as B), fl(wb Cb))) Rcp_hw(ao))` (`arith::CompositeInput::coverageWeights`); the first layer of a list is copied. Evidence: `group-coverage-order` (24 maps), `group-masks` s2-s3 and `quantisation-thirds` exact on every map (`masks-levels.json` entry `group-coverage-order`). Under the earlier profiles a transparent backdrop passes the source through and a partly covered backdrop uses the general formula in float32 with a correctly rounded reciprocal (within one export step of Painter on 32-bit float and RGB16 channels).
- **Instances** evaluate their source layer in their own position; **invisible** layers are skipped; an **empty mask** is its background (White 1, Black 0); a disabled mask is 1.
- **Masks** (`phase1.11`, `parity/semantics/masks-levels.json`). A layer's or group's mask is mono and independent of the channel (one raster, cached once, for every channel of the layer). It starts from its background and runs its visible effects bottom-up: a fill effect blends its mono source (a uniform colour's mean, or a bitmap's first component, projected like any fill) with its own mode and opacity through the **effect mix** `v = a + (r - a) alpha` for every mode (the layer mix `a (1 - alpha) + r alpha` misses 6 of 65 536 texels of `mask-precision` s3), `r` the mode's kernel clamped to [0, 1], so subtraction is the `Subtract` kernel; a levels effect remaps the mask (Painter's API gives it no blending). The mask is stored at **16 bits** after every effect on every channel format (`mask-precision`: RGB16, L16, RGB32F, sRGB8 and L8 exact on both recordings; an 8-bit mask misses thousands of texels). A `Mesh` geometry mask multiplies the mask (its raster from `IGeometryMaskProvider`); `UVTile` geometry masks fail. The layer blends with opacity × mask. A group's mask scales its isolated composite as a layer's does (`group-masks` s2-s3: exact where the child's mask is 0 or 1).
- **Content effects** (`phase1.11`). A fill layer's content runs through its visible content effects in list order, stored in the channel format after each: a fill effect blends its source for the channel (when active on it) with its per-channel mode and opacity through the effect mix; a levels effect remaps its affected channel only. **Levels** (arith::Levels): `t = (v - in_min) Rcp(in_max - in_min)` with the hardware reciprocal; `clamp` limits t to [0, 1] (the output range is never clamped); a gamma other than 1 gives `sign(t) pow(|t|, gamma)` through the hardware pow; `out = fma(t, out_max - out_min, out_min)`. Exact: `levels-clamp` (16 maps, both recordings), `effect-order` s6 (RGB16 and sRGB8). The order of fill and levels effects is the documented list order; every Tier 0 order but s6 and s7 holds the Blur filter (P3-PROC), so it is not yet observed.
- **Height override** (LAY-03). `EffectiveBlending(layer, channel)` reads the blending that applies to a node on a channel: its own entry or Normal at 1; a group's `Height` entry is the blending of its composite on Height (the per-group override), its children keep theirs.
- **Cache shape** (planning review: settled before mask effects depend on it). Content and mask effect chains are nodes keyed by chained hashes (`CacheKind::Effect`, `CacheKind::Mask`); a layer's contribution hash covers its final content and mask hashes. An upstream change (a mask or content effect, as an anchor's would be) re-evaluates only its chain from the change up and the prefixes above the layer; the masks of a layer are shared by its channels (`uzp-evaluator-tests masks`).
- **Height and normals** (`phase1.12`, `parity/semantics/height-to-normal.json`, decisions 064, 065, 079 and 080). The virtual normal maps read the Height read-out **before** its write rule (`EvaluateFloat32Readout`: the root's read-out blend into a raw 32-bit float tile, `BlendOp::rawOutput`; at opacity 0.75 and 0.1 the stored half is not what Painter reads), the Normal channel's root list from a transparent start (`EvaluateIsolatedRoot`: colour X and coverage a, before the read-out) and the bound Normal mesh map (its 16-bit codes uploaded as float32 operands). Per texel, rows top first, wrap-around at the set border: Sharp `v = (h(-1,0) - h(0,0), h(0,0) - h(0,-1), 100 / W)`, Smooth (Sobel) `v = (L - R, B - T, 800 / W)` with `(a + 2b) + c` sums (`HeightZ`, recorded at W = 256 to 2048); `H = normalise(v)`, `A = normalise(reoriented(F, H))` with F the decoded mesh map (y negated in the DirectX convention) or flat, `n = normalise(reoriented(A, C))` with the normal-map steps of `arith.h` (hardware rsqrt); C = decode(X) at full coverage, flat at coverage 0, else decode(X hw::Rcp(a)) turned toward (0, 0, 1) by a with `hw::Acos` (the GPU's Vulkan arccosine), `hw::Sin`, `hw::Cos`; `Normal_OpenGL = fma(n, 1/2, 1/2)`, DirectX negates `n.y` first. One `VirtualNormalOp` per tile reads the nine height read-out tiles around it, the Normal root list and the mesh tile. The method is the texture set's `height_to_normal_method`. The Normal channel's read-out composites its layers over (0.5, 0.5, 1) (`ChannelDag::readoutBase`; an empty channel exports its template base 127/255); it imports a normal-map bitmap with its green codes inverted (`max - g`) in both conventions. On the Height channel a bitmap texel enters the bilinear filter as 2t - 1 (`ProjectTexel(..., signedRange)`; the filter accepts signed texels). Exact on every r1 map of every recorded golden; GPU = CPU bit for bit (`height-normal-gpu-vs-cpu`). Every result carries `NormalTag`: `combined` with its relief round (revision, Height read-out hash, method), or `geometry_only` for the pass-through of the bound Normal mesh map (codes unchanged, green inverted across conventions). Refused until recorded (`unsupported_source`): sets other than square 256, 512, 1024 or 2048 px; a mesh map in the combination that is 8-bit, of another size or in the other convention; a DirectX project's Normal channel other than one bitmap fill in Normal mode at opacity 1 without mask or effects.
- **Diagnostics** (`phase1.13`, decisions 075, 076; LAY-09, LAY-14, EXP-04, DIA-01). Exports of the general evaluator, never a separate path.
  - `isolate(node)` hides a layer, group, instance or effect in a private copy of the revision (`HiddenCopy`) and evaluates the copy. Nothing is committed, so the document, its revision, operation records and save state never change, also when the evaluation fails midway. The tiles below the hidden node come from the cache.
  - `contribution(node)` is full − isolated: one float32 subtraction per sample of the decoded values, signed and never clamped, on any channel or virtual normal map.
  - `material_views(material)`: a material is a fill layer or group. Its region is its effective mask, the float32 product of its own mask and every enclosing group's, each evaluated by the engine's mask chain (`BuildLayerMask`, `EvaluateLayerMask`); a texel is inside where the product is at least 1/2.
    - The ID view is the bound ID mesh map inside the region. Its leaks are the texels whose code triple is not the region's modal one.
    - The BaseColor, Height, Normal, Roughness (`SpecularRoughness`) and Metallic (`BaseMetalness`) views are the full evaluation inside the region. Their leaks are the texels whose full value differs bitwise from the material's solo evaluation, in which every layer that is neither the material, an enclosing group nor inside it is hidden.
    - A view the set or stack cannot give is listed as missing.
  - `region_stats(map, mask)` gives counts, thresholded and weighted coverage, per-component min, max, mean (correctly rounded sum) and p10/p50/p90 (linear rule), and the luminance and HSV saturation of three-component maps.
  - Each diagnostic is an export-plan source: `srcMapType` `diagnosticMap` with `srcMapName` `<kind>/<map or view>/<uid>`. The statistics are canonical JSON (`RegionStatsJson`).
  - The differences, masking and statistics run on the CPU over read-back values, so the GPU and CPU outputs are the same bytes (`diagnostics-gpu-vs-cpu`).
- **Sources** (`phase1.8`, `parity/semantics/colour-transfer.json`). Uniform colours are taken as linear and stored like a channel value, then read back (`blend-modes.json` `uniform_operand`; a grey channel takes the mean of the three components: of their float32 values under the earlier profiles, of the components as given under `isolated-coverage-weights`); sRGB, Working and Raw give the same codes under legacy colour management. sRGB8 channels store through the recording GPU's float-to-sRGB8 conversion and read through its decode (not the IEC rounding: 2 936 of 65 536 operands differ), which makes the uniform ramps, the sRGB8 export and every sRGB8 stack golden exact. Bitmaps are bound by content hash (LAY-13: the alias plays no part), decoded once, and in the colour spaces Raw, Data, DataSigned and NormalXYZLeft a code `c` is the linear value `float32(c / M)` stored with the channel's write rule (exact on RGB16, sRGB8, RGB8, L16: `blend-inputs`). An sRGB bitmap (Painter's default for a colour bitmap on BaseColor; also Legacy sRGB) is decoded texel by texel to float32 before the projection samples it, then stored on its sRGB8 channel (decision 174): an 8-bit code is the GPU's sRGB8 texel (`Srgb8Operand`), a 16-bit code the GPU's float32 shader decode with the contracted `fma(x, r, 0.055 r)` and the measured pow, and a grey bitmap feeds the three channels. Exact on every texel, r1 and r2, at 1:1 (`virtual-maps-converted` s0-s1 and its OpenEXR twin, `export-probes-config`, `export-probes-naming`: `tests/export/test_export_plan.py::test_srgb_bitmap_exact`; `export-ocio-encode-legacy` s3, the 8-bit ramp, and s5, the ramp in a group masked by grey A: exact against r1, its unstable r2 judged through EXC-006, decision 152; `export-bit-depth` s4, s5, s7, 16-bit grey; `srgb-bitmap-variants-v2` s0, 8-bit grey), magnified by BilinearHQ and under Nearest at scale 2 (`srgb-bitmap-variants-v2` s2, s3, 16- and 8-bit colour: `tests/export/test_export_encoders.py::test_srgb_variants_equal_painter_files`); bilinear minification of an sRGB bitmap is unrecorded and fails with `unsupported_source`. On an L8 BaseColor, Specular or Emissive (decision 208, `export-l8-material` s0 and s1) a grey sRGB bitmap at 1:1 is read decoded and stored with the L8 write rule: a 16-bit code through the same float32 shader decode, an 8-bit code through that decode of `float32(c / 255)` rounded toward zero to a binary16 (not the sRGB8 texel, which misses 30 of the 256 codes; the IEC decode rounded to nearest misses 13): all 256 codes of grey A and of the 8-bit ramp, every map, PNG 8, PNG 16 and OpenEXR 32f, r1 and r2 (`tests/export/test_export_encoders.py::test_l8_material_channels_equal_painter_files`); a colour bitmap, any resampling and OCIO there are not recorded and fail with `unsupported_source`. Working and Legacy Linear read codes as Raw does (s6, s7). Painter refuses sRGB on a user channel in every format but sRGB8 and on a mask's mono source (s4, s5: the bitmap stays Data), and so does the facade; an sRGB tag there fails with `unsupported_source`, as it does, not recorded, on any other channel that is not sRGB8; on the Height channel the value is `2 t - 1` over the signed channel's base 0 (`height-normal-plane-amplitudes` s0-s3 exact; the templates' Height base is 0 and its 16-bit PNG export is `(h + 1) / 2`). OCIO with Painter's substance config (`kPainterOcioConfigSha256`, decision 190) stores the codes Legacy does for every source Session O records (`export-ocio-encode`: uniform colours in sRGB, unset and Raw; an 8-bit colour bitmap in sRGB on BaseColor at 1:1; a 16-bit grey mask source at 1:1), except an 8-bit colour bitmap in Raw on an sRGB8 channel, whose code c is float32(c / 255) rounded toward zero to a binary16 (`OcioRawDecoded`; c / 255 misses 4 of the 256 codes); every other bitmap use under OCIO, and any other OCIO configuration, fails with `unsupported_source` (`tests/export/test_export_encoders.py::test_ocio_encode_equals_painter_files`).
- **Projections** (`phase1.8`, `parity/semantics/uv-sampling.json`). `Fill` is the identity with `Repeat`; `UV` applies the documented transform about the UV centre in double (the offset before the scale and the rotation, decision 056), `Nearest` (exact at every scale; a tie between two rows takes the upper one, the GPU's point sample of the bottom-up bitmap: `srgb-bitmap-variants-v2` s3) and the bilinear filters as the recording GPU's linear filter of a float32 texture, measured at every 8-bit weight pair (`BilinearFilter`: 8-bit weights, operands with 28 bits below the largest weighed texel's exponent, one rounding, ties up; the Height channel's signed texels 2t - 1 by sign and magnitude, ties away from zero; `resample-uv` magnification and 1:1 exact under every filter and wrap mode, `phase1.9_compositor-resample-gaps`). A wrap mode that can leave texels uncovered gives the content tile a coverage plane, so the fill keeps the value below there. Bilinear minification goes through `texture_unit.h`, the recording GPU's anisotropic texture unit replicated from two measured tables (decisions 061, 071, 083, 084), with Painter's float32 UV, mip chain, BilinearSharp bias and BilinearHQ supersampling around it (decisions 060, 084): exact on every axis-aligned user of the minifying goldens, CPU and GPU. Minification at other rotations, of non-square or non-power-of-two bitmaps, on non-square sets, with a one-axis wrap or on the Height channel (Painter filters the signed heights; their minification is unmeasured), physical-size scale modes and non-power-of-two sets fail with `unsupported_source`. Island edges: the evaluator fills the whole UV tile; on every texel-centre-covered texel of the imported mesh's UV raster it equals the goldens (sphere, bevelled cube), and texels outside the islands are export padding.
- **Kernels** (`phase1.10`, `parity/semantics/blend-kernels.json`). Every documented `BlendingMode` but `PassThrough` (a group placement) has a kernel, per channel with per-channel opacity. The 24 separable modes (Normal, Replace, Disable, Multiply … PinLight) equal the Tier 0 sweeps exactly on every format (RGB16 at opacity 1 and 0.5, sRGB8 at 1 and 0.5, RGB8, RGB16F, L16, RGB32F at 0.25) against both recordings. Two facts made them exact: Painter divides and takes square roots with the GPU's faithful (not correctly rounded) float32 instructions, reproduced from the measured tables of `hwmath.h` (Divide, InverseDivide, ColorBurn, ColorDodge, VividLight: reciprocal; SoftLight: square root), and ColorBurn's opacity mix is one rounding, `fma(a, 1 - alpha, r alpha)`. Explicit fused multiply-adds (the float32 rounding of the exact `x y + z`) only where the goldens show them: Exclusion, Screen, HardLight and Overlay (upper branch), SoftLight, ColorBurn (kernel and mix) and the normal-map dot products and reoriented mapping; contraction stays off everywhere else. The normal-map modes (`phase1.11`, decision 053) decode, rotate the upper normal toward (0, 0, 1) by the opacity, combine (whiteout, reoriented normal mapping with `r.z = t.z (d - u.z)`) and normalise through the hardware reciprocal square root. The rotation is n' = (n.x k, n.y k, cos(a t)), with t = pi/2 - asin(z) and k = sin(a t) rsqrt(fma(-z, z, 1)). Its sine and cosine come from tables measured on the recording GPU (`hw::Sin`, `hw::Cos`, `trig-hardware`), and its arcsine is the GPU's GLSL `asin` polynomial (`hw::Asin`). These modes are exact at every recorded opacity (0.1, 1/3, 0.5, 0.7, 0.99 and 0.25 included), on every format, on a flat normal and on the Normal channel. The component modes (Tint, Saturation, Color, Value; `phase1.11`, decision 073) are HSV with the value doubled. The hue is measured from the smallest component: h6 = fma(p - (q + 3e), rcp(d + e), C), e = 2^-12, with h = h6 float32(1/6) plus 1 when negative and 1.0 kept. The weights are centred on the primaries, for example green fma(-6, |h - float32(1/3)|, 2) (`arith.cpp Hue`, `HueWeights`). They were identified on `blend-component-hue` and are exact on every format of it and of the held-out `blend-component`. Correctly rounded reciprocal and square root (the hardware result corrected with exact double residuals on the GPU) remain for the compositing arithmetic (the coverage-weighted source-over of `isolated-coverage-weights` takes the hardware reciprocal); IEEE minNum/maxNum where the fit uses numpy `fmin/fmax`, NaN propagation where it uses `minimum/maximum`. GPU = CPU bit for bit for every mode (`kernel-sweep`, `gpu-vs-cpu`).
- **Cache.** Every subtree hash is seeded with the project's profile id (tiles of two profiles never serve each other), channel, format and the set resolution, so a resized set never reuses a tile of the old size. Node outputs are tiles keyed by `(node, kind, subtree hash, tile)`: `Content` for a layer's bitmap tile, `Prefix` for the accumulator of a layer list after a layer (chained hashes from the list start, which includes profile, channel, format and base). An isolated root adds a `Readout` tile (the root composited over the base), looked up first. A list is evaluated from its highest cached prefix upward, so an edit re-evaluates only the layers above it; untouched channels and tiles are served whole. Subtree hashes cover only evaluation-relevant fields (names and UI state do not invalidate).
- **Admission.** Limits come from `render::AdmissionBudget` (13 §6). `CheckTextureSet` admits a set when its final tiles plus a three-tile working set fit; `TileCache::Allocate` evicts least recently used unpinned tiles and fails explicitly (`tile_budget_exceeded`) when pinned tiles leave no room; the evaluator flushes queued GPU work and releases finished inputs before failing.

## 3. Templates (`assets/templates/`)

One JSON per shipped Painter 12.1.0 template (26), `default.json` for the project created with no template, and `channel-defaults.json` for channels added afterwards (an entry that names a `format` applies to that format only, and a type may have one per format: the sRGB8 Specular and Emissive of decision 126, their L8 twins of decision 204). Schema `uzpainter/template/1`: `id`, `name`, `kind` (`project` | `channel-defaults`), `painter_template` (the shelf path the template reproduces), `provenance` (channel set: the `project-templates` capture; base values: the `base-values-<template>` golden; record hashes), `channels[]` with `type` (`ChannelType`), `format` (`ChannelFormat`, project templates only), `base` (three float32 components) and `base_provenance`:

- `observed`: the private golden, its record hash, the map and the 16-bit export codes the base reproduces (the base is the nearest float32 to `code / 65535`, checked to write back to the code; the signed Height channel exports `(h + 1) / 2`, so its observed code 32767 is the base 0). An sRGB8 BaseColor or Specular is observed where an OpenEXR 32f export of the empty channel shows its linear value: its golden is that export, and `export16` the base-values code it encodes to;
- `fitted`: a published fit (`height-to-normal.json` flat normal, `ao-mixed.json` white AO);
- `inferred`: the golden's 16-bit export code is observed, but a range of linear values writes it and no OpenEXR export of the empty channel identifies one. The sRGB8 BaseColor and Specular of the shipped templates hold linear values (decision 126: the export writes their sRGB encode): OpenEXR 32f shows every shipped template's base (decisions 168, 169, 172): `float32(0.8)` on the default and the four OpenPBR templates, `float32(10/255)` on the four sRGB8-Specular templates, `float32(127/255)` on the other 18. Since decision 169 no shipped entry is `inferred`. The export still refuses any file that depends on an `inferred` base (`unsupported_source`), so an entry added from a PNG code alone stays refused until a recording settles it. Dota 2's L8 Specular is observed the same way (`float32(10/255)`); its PNG export is refused (decision 169);
- `unobserved`: no document map exports the channel (coat, fuzz, subsurface weight/colour, tangent); authored by analogy and listed as such in the local run report. A channel type absent from both a template and the defaults fails evaluation with `missing_base_value`.

Authored by UzmiGames; never generated from a capture (the goldens are compared with the files in the local run, `test_template_channel_sets_equal_the_capture`, `test_base_values_equal_the_empty_project_exports`). `TemplateLibrary::DefaultDirectory()` is `assets/templates` beside the executable (installed by `zig build painter` and `evaluator-tests`).

## 4. Out of this profile (explicit failures, capability gaps)

The capability manifest lists every case below under the context `compositor` (decision 081, `tools/capabilities/compositor-capabilities.json`), `supported` with its goldens or `release-gap` with its owner task. A request that adds or changes a node using one fails with `NotYetSupported` before any mutation (`support.h`, decision 082): the evaluator's own `unsupported_*` refusals have that API class too, and stay as the second line for documents opened from disk and for the refusals that need decoded inputs (bilinear minification outside the texture unit's domain, the height-to-normal cases). Parent run: `python tests/evaluator/union_run.py` runs every child's Tier 0 golden set on DX12 twice and writes `parity/reports/phase1/compositor-core.md`.

Phase1.12 additions (decision 079): the virtual normal maps on sets other than square 256, 512, 1024 or 2048 px, with a Normal mesh map that is 8-bit, of another size or in the other convention, and a DirectX project's Normal channel other than one bitmap fill in Normal mode at opacity 1 without mask or effects fail with `unsupported_source` (the last also before mutation, `support.cpp`); several Normal layers at partial coverage and the signed bilinear filter with non-dyadic weights are modelled but unrecorded (`height-to-normal.json` gap `height-normal-unrecorded-inputs`).

Paint layers and effects, generator and filter effects (P3-PROC), compare-mask, colour-selection and anchor effects (P4-NODES), `UVTile` geometry masks, `Material` source mode, procedural/vector/font/reference sources, 3D projections and symmetry, physical-size UV scale modes, bilinear minification of rotated footprints, of non-square bitmaps and on the Height channel, OCIO colour management outside what Session O records (decision 190). Implemented but not exact against a golden: under the earlier profiles `isolated-linear` and `isolated-half-alpha`, the float32 source-over onto a partly covered backdrop on 32-bit float and RGB16 channels (`group-masks` s2-s3: 57 RGB16 and 20 631 RGB32F values of 196 608 off by one step; `quantisation-thirds`: 5 of 16 float values; decision 044; exact under the current `isolated-coverage-weights`, decisions 058-059); the RGB8/L8 coverage rule at an 8-bit tie (no golden; plain 8-bit write kept). Unobserved and implemented by analogy: 8-bit bitmaps, `RepeatHorizontally`/`RepeatVertically`. Unobserved and refused: bilinear minification of an sRGB bitmap, a bitmap colour space outside Raw, Data, DataSigned, NormalXYZLeft, Working, sRGB and the Legacy Linear and sRGB spaces (phase1.15_compositor-colour-fits, decisions 130 and 174). Unobserved and refused: an sRGB bitmap on a channel that is neither sRGB8, a user channel nor an L8 BaseColor, Specular or Emissive, and on those L8 channels a colour or resampled one (decision 208). Refused as Painter refuses it: an sRGB bitmap on a user channel that is not sRGB8 or as a mask source (decision 174). Each fails before any work with `evaluator:unsupported_*` naming the node and the task that owns it.
