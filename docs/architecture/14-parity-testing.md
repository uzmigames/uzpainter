# 14 — Parity testing

Implements D13 (`05-resolution.md`) as updated by the owner's answers of 2026-10-10 (`docs/open-questions.md`): Q1 exact equality with an exception register (decision 017), Q2 Painter's Iray as the render reference (decision 018), Q6 migration through the documented API (decision 020), Q9b the owner's machine as holder of the private store (decision 022), with GPU and oracle checks run locally there rather than on a CI runner (decision 028). Requirements: G-04, EXP-05, NFR-02, ARC-09, ARC-10, CLR-05 (`docs/prd.md`). Acceptance premise: decision 001; licence/clean room: decision 002 (`docs/licensing-and-clean-room.md`).

## 1. Acceptance sentence (binding)

> Default acceptance is equal native decoded texture values and the agreed reference render output. Every divergence is a failure unless an owner-approved, versioned exception explicitly covers that domain and metric. Explained differences are still failures without that exception. Diagnostic metrics do not grant an exception.

Equality is exact (Q1): there are no preset tolerances, and the exception register (§5) is the only way a non-zero difference passes. The agreed reference render output is Painter's Iray (Q2). Iray is a stochastic renderer, so pixel-exact equality between UzPainter's path tracer and an Iray reference is **not achievable**: every Tier 3 pass is an owner-approved register entry derived from the measured noise floor, and without one Tier 3 is blocked, never passed (`07-preview-and-render-parity.md` §4).

Three results are always reported separately: **oracle stability** (does Painter reproduce itself?), **UzPainter repeatability** (same build, same inputs ⇒ same bytes) and **equality to Painter**. Max error and affected-texel/pixel counts are always visible next to any mean or percentile; a perceptual metric (FLIP) is a diagnostic, never a gate.

## 2. The oracle and how it is recorded

- Oracle: Adobe Substance 3D Painter 12.1.0, including its Iray renderer, on the owner's machine (where GPU and oracle checks run locally, decision 028), started with `--enable-remote-scripting`. UzmiGames recorder scripts (`tools/parity/recorder/*.py`, written from `python-doc`) use **Painter's documented Python API for state** and a **qualified, permitted capture procedure for pixels**: texture exports through the documented `export_project_textures`, and Iray renders through the procedure of `07-…` §2.2 (settings sheet, convergence check, Save Render, readiness and current-frame verification), qualified in Phase 0 (P0-FEAS-RENDER) before any render golden is admitted. No private interface is inferred from historical implementation files, and the community MCP bridge is never used (its known defects — Paint active-channel false success, mask `None` crashes, wrong blend channel, non-atomic cleanup, `set_layer_mask(enabled=false)` deleting the mask, no float bit depths — make bridge-recorded recipes untrustworthy; `docs/analysis/substance-parity/06-mcp-tools-inventory.md` §9, historical context). A recipe captured through the bridge is re-validated against Painter before it becomes a fixture.
- The `substance_painter` facade under test holds documented symbols only. The pipeline's private viewport-capture call (`save_viewport`) is served by a shim in the UzmiGames pipeline adapter (`10-python-api.md` §2), never by the facade or the recorder.
- A golden is `{inputs, instruction sequence, effective defaults, Painter build, project settings, resource hashes, bake backend, render state} → {outputs}` where outputs are 16-bit (or float) exports via `export_project_textures`, API readbacks, and converged Iray renders with their settings sheet. Every golden is recorded at least twice (same session; after save/reopen); Iray references are recorded twice in separate Painter sessions plus once at k·S samples (`07-…` §2.2). Oracle stability is measured before a golden is admitted.
- Migration (Q6): Tier 1 fixtures are rebuilt through Painter's documented API, proven by output equality; there is no `.spp` reader. Brush strokes are out of scope (Q5). If a required fixture cannot be migrated through documented APIs, record `not_migratable` with the reason and keep its affected gate blocked. Excluding or replacing that fixture requires an explicit owner scope decision recorded in the capability manifest and gate report; reporting the limitation alone never closes the gate. Existing paint content may be imported as bitmaps when the documented export route preserves the required output. Settling check: a gate fixture marked `not_migratable` with no owner scope decision fails the gate, even if every remaining fixture passes (`docs/dag.md`, corpus migration assumption).
- Observing Painter's behaviour this way is the only permitted way to learn undocumented semantics (decision 002); every recorded output is private test data (§6).

Comparison is on decoded pixels at native depth (never through 8-bit viewers; Pillow truncates RGB16 — `A3D\Docs\Lessons\export-spp-maps-native-precision.md`). Channels are classified by their *measured* storage format, not by name; no half-float epsilon is applied by map name.

GPU tiers run on both backends once the Vulkan backend is qualified (P3-VULKAN): Tier 0–2 outputs on Vulkan must equal those on DX12 byte for byte, and any difference passes only through §5. The realtime viewport (`painter_viewport`) is not a tier: its UzPainter-vs-UzPainter regression goldens are repeatability checks (`07-…` §6), never parity evidence.

## 4. Diagnostics reported with every comparison

Per map: max |Δ|, mean |Δ|, p99 |Δ|, count and percentage of differing texels, difference map, per-region breakdown by the asset's material masks; for normals, angular max/mean and non-finite/unnormalised counts; for IDs/opacity, exact label/alpha equality and edge coverage; for renders, the statistics of `07-…` §4 per material region (including mean signed Δ with its standard error and the downsampled statistics) next to the noise floor and UzPainter's own re-render statistics; for lossy derivatives (BC, mips), decoded compression error against the canonical map (a separate contract from authoring equality). FLIP is computed with NVIDIA's reference implementation (`NVlabs/flip`, BSD-3-Clause), pinned by version and hash in the comparison tool and listed with its notice in the dependency inventory (`docs/licensing-and-clean-room.md` §3); it is diagnostic only. Difference maps and region crops are derived from oracle pixels and stay in the private store; public reports carry numbers only.

## 5. Exceptions

Exact equality is the rule and there are no preset tolerances (Q1). An exception is the only way a non-zero difference passes. It is proposed with: domain (channel/asset/map, render fixture class, or backend pair), metric and bound, the evidence that the oracle itself is unstable or that the difference is irreducible (for Tier 3: the measured noise floor and every `uncontrolled` render setting the reference relies on, `07-…` §2.1), and a defect-detection test showing the bound still catches intentional errors (sparse seams, alpha defects, one wrong texel region; for renders a missing channel, a wrong lobe, a roughness offset, a wrong environment rotation). The owner approves it; it is recorded as a decision under `.rulebook/decisions/` and as a versioned entry in `parity/exceptions.json` (numbers and hashes of the private evidence); every report lists the entries it relied on. For Tier 3 the register is the only route to a pass; a Tier 3 entry never relaxes Tiers 0–2 and never covers a structural difference (wrong material binding, missing map, wrong geometry, camera or environment). Diagnostic metrics never grant an exception.

## 6. Corpus storage and access (private oracle)

- **In the public repository** (independently authored or public data only): `parity/manifests/**/*.json` — independently authored test inputs (fixture descriptions, UzmiGames-written instruction sequences, UzmiGames-authored meshes/masks/environments, CC0 or own), the settings a test applies, public-documentation-derived expectations, software identities (Painter build id, UzPainter build hash) and the SHA-256 of every private oracle record; `parity/semantics/*.json` — independently derived fitted formulas, their public sources and residuals (numbers); `parity/exceptions.json`; comparison reports (numbers only).
- **Only in the private store, never in the repository and never shipped:** every recorded Painter output — exported maps, Iray references, API readbacks (JSON included), effective-default and template captures, operator-recorded render settings and settings-panel evidence, asset recipes extracted from Painter projects — and anything derived pixel for pixel from them (difference maps, crops). Public templates and default tables are independently authored from documented semantics with provenance; raw captured records are never published, whatever their file format.
- **Guard:** a pre-commit check, also run in the local full gate (decision 200), rejects any file whose hash appears in the private store's index or that does not validate against the public manifest schema — content checks, not only PNG/EXR or Adobe signatures — and passes independently authored fixture images and expectation JSON (P0-STORE).
- **Private oracle store:** a content-addressed folder on the owner's machine, addressed by SHA-256 and configured through `UZP_PARITY_STORE`. `uzpainter parity fetch <manifest>` resolves the blobs a manifest names; `uzpainter parity verify` checks hashes; `uzpainter parity record` (owner's machine only) stores newly recorded oracles and writes their hashes into the manifest. Backups are the owner's private copies; the store is never uploaded to a hosted service.
- **Oracle access (decision 028):** the owner's machine (GPU, licensed Painter, the store) is the only machine that compares against recorded Painter values (Tiers 0–3), in local runs whose report is the evidence; there is no GPU CI and no self-hosted runner. There is no hosted CI either (decision 200): the CPU lane runs locally, in the coordinator's full gate before the owner pushes. Where the store is missing, oracle tests skip with an explicit reason; the CPU lane runs everything that needs no oracle record and compare only against independently authored public expectations (unit tests, repeatability, schema validation, failure injection). A missing blob fails the comparison as `oracle_unavailable`, never as a pass.
- Retention: oracles are immutable per Painter build; a new Painter build gets a new corpus directory; old corpora are kept for regression history.

## 8. Regression policy

- Goldens are immutable; a changed golden needs a reviewed provenance note (Painter version change or a proven bad fixture) and never comes from the implementation under test.
- Any tier failure blocks the affected milestone; release fails on any required unsupported behaviour, unapproved difference or blocked Tier 3 comparison.
- Failure injections are part of the suite: cancel mid-bake, disk full during save, stale revision, worker death, device removal, save/reopen/export cycles, worker death after the durable commit and before the acknowledgement (retry with the same idempotency key returns the committed outcome; a changed request with the same key is rejected).
- Every result carries hardware, driver, backend, build hash, resource hashes and the exceptions used.
