# 12 — Mesh import and texture sets

Implements D11 (`05-resolution.md`) under owner answer Q8 (decision 021: zero dependency on UzEngine). Requirements: PRJ-01, PRJ-02, PRJ-04, PRJ-07, PRJ-08, PRJ-09, PRJ-10, INT-10, INT-12, QG-02 (`docs/prd.md`). Engine facts: `docs/analysis/uzengine-renderer/05-mesh-import.md`, `10-review-response.md` (§4.2 stride defect, §7 FBX normal recomputation).

## 1. Scope

UzPainter imports meshes with its own raw loader into a corner-preserving `TexturingMesh`; it neither vendors nor calls UzEngine's cook path (`.uzmesh`/UZMS/UZMH; `13-engine-integration.md` §2), which selects the first mesh only, runs LOD/SDF work, recomputes FBX normals by default (`r.Mesh.NormalImportMode = 1`) and has a confirmed 32/48-byte stride defect in the glTF route (`mesh_importer.cpp:734-739`, `mesh_io.cpp:152,171-186`). The external UzEngine consumer fixture (`07-preview-and-render-parity.md` §1) runs in UzEngine's own executable; its mesh route avoids that defect or is qualified first — a condition on the consumer test, not a UzPainter dependency.

```
TexturingMesh { objects[] {name, transform, triangles[] {corner ids}},
                corners[] {position id, normal, uv0, tangent xyz + sign (computed), material id},
                positions[], materials[] {name, index}, units {source, scale_to_internal},
                hashes {positions, uvs, corner_normals, triangulation, materials}, certificate }
```

## 2. Formats and parsers

| Format | Parser | Rules |
|---|---|---|
| OBJ | Own parser | `usemtl` → material/texture set; `o`/`g` → object names for geometry masks; negative indices, missing normals/UVs (flagged), multiple UV sets (first used, others recorded) |
| FBX | ufbx (vendored from upstream under its own licence, `docs/licensing-and-clean-room.md` §3) | All meshes, instances and transforms; source units via ufbx; V flip recorded; corner normals preserved (no recomputation) |
| glTF / GLB | fastgltf (vendored from upstream) | All meshes/primitives; `TEXCOORD_0`; stored `TANGENT` recorded but tangents are regenerated for consistency; `GltfSettings.invert_normal_maps` honoured for imported material textures (Painter behaviour) |
| High-poly | same parsers, streamed | Positions, indices, optional normals, vertex colours and material ids as side streams straight into Embree geometry, or into acceleration structures UzPainter builds with explicit vertex strides for the optional GPU baker (`06-baking.md` §1); never through the texturing mesh path or a fixed-stride path such as UzEngine's `BLASManager` (48-byte stride, opaque) |

Painter also accepts `dae`, `ply`, `usd`; they are release gaps in the capability manifest.

## 3. Contracts

- **Triangulation.** Already-triangulated input is kept exactly (`PRJ-01`); polygonal faces are triangulated by a documented fan rule and flagged in the certificate; the rule is a Tier 0 item compared with Painter's result on the same quad mesh. Painter 12.1.0 fans every polygon from its last corner, whatever its shape, planarity or shortest diagonal (a quad c0 c1 c2 c3 is split along c1-c3); UzPainter does the same (`parity/semantics/polygon-triangulation.json`, `exact`; `parity/reports/phase1/polygon-triangulation.md`).
- **Units.** Painter's unit is centimetres; `mesh_unit_scale` 0/None means "use the file unit", otherwise the given scale (`project.Settings.mesh_unit_scale` in the public API documentation; `docs/analysis/substance-parity/05-project-and-spp.md` §1.1 is historical context). UzPainter stores `units {source, scale_to_internal}` and applies them to cage/ray distances, physical-size projections and the camera; the effective scale is in every receipt (PRJ-07).
- **Identity.** Material identity (name + index) and object identity are separate; duplicate material names are an import error unless `allow_duplicate_material_names` merges them explicitly; texture sets are created one per material in file order (PRJ-02).
- **Tangents.** MikkTSpace (Mikkelsen's reference `mikktspace.c`, vendored from upstream under its own licence) per corner; `TangentSpace.PerVertex` interpolates the bitangent, `PerFragment` rebuilds it per texel from interpolated N and T with the stored sign. When a project does not set the mode, UzPainter uses `PerVertex`, Painter 12.1.0's observed default; `PerFragment` is used whenever the caller sets it, as the Assets3D pipeline does (decision 031). Settled by the Phase 0 fixture (`parity/NORMAL-CONVENTION.md`, verdicts in `parity/semantics/tangent-frame.json`, numbers in `parity/reports/phase0/normal-convention.md`): with the sampler transform `mikktspace.h` prescribes (the exact inverse of `normalize(x vT + y vB + z vN)` on the unnormalized interpolated vectors), the prototype's `PerFragment` and `PerVertex` bakes equal Painter's bakes with the same project setting to within 1 code at 16 bits (ties of the final rounding), while the two modes differ from each other by about 69 codes on average; the OpenGL format encodes +v in green and Painter's DirectX bake is the green code inverted (65535 − g). Painter's own project default (tangent space not set) bakes exactly as `PerVertex`, hence the unset default above; the pipeline sets `PerFragment` explicitly. UzEngine's executable, shading a map on a mesh cooked by its `uzmesh` from OBJ, reads green as −v (DirectX convention): an OpenGL map needs its green inverted for that consumer path.
- **Orientation.** Image rows are stored top-down; the pipeline's mask tools write rows flipped relative to their raster arrays (`A3D\Docs\Pipeline\Pintura\regularize_garment_trim.py`); the import of `M_*.png`/`T_*.png` follows PNG order and a directional fixture confirms it (INT-12).

Implementation (`src/mesh/`, `phase1.4_mesh-importers`; `zig build mesh-tests`, tests in `tests/mesh/`):

- `texturing_mesh.h`: the §1 structure. `positions[]` are the file's positions in file order and file units in the space the file authors them (nothing welded or compacted); `corners[]` are the face corners as authored (an OBJ `f` reference, an FBX polygon vertex, a glTF index) with position id, authored normal ((0, 0, 0) and counted when absent), first UV set ((0, 0) and counted when absent), material id and an empty tangent slot for `phase1.5_mesh-tangents-certificate`; `objects[]` carry a column-major transform to the file's scene space (one object per instance) and their triangles. UVs follow the OBJ convention (v up; tile 1001 is the closed 0–1 square). The five hashes are SHA-256 of little-endian streams: positions (float32 xyz, then every object's transform as 16 float64), uvs (float32 uv0 per corner), corner normals (float32 xyz per corner), triangulation (per object its triangle count and corner ids, then every corner's position id, all uint32) and materials (per material its index, UTF-8 name and a 0 byte, then every corner's material id).
- Triangulation (`mesh_builder.h`): a 3-corner face is one triangle with its corners in order; an n-corner face becomes (c[i], c[i+1], c[n−1]), i = 0..n−3, over the face's own n corners (the fan from the last corner, Painter's split measured by the Tier 0 golden `phase1/mesh-import/polygon-triangulation`, `python -m tools.parity.polygon_triangulation`), and counts in `ngons_triangulated`. ufbx's ear-clipping triangulation is not used.
- OBJ (`obj_parser.h`): `v`/`vt`/`vn` in file order; 1-based or negative (relative to the elements defined so far) references; `o`/`g` lines start a new object when the name changes, faces before them belong to the object `default`; materials are ordered by their first `usemtl` and kept only when faces use them, faces before any `usemtl` use `default`; `mtllib` names are recorded, libraries are not read; `l`/`p` are counted as skipped. OBJ states no unit (`source: unspecified`).
- FBX (`fbx_import.h`, ufbx with no unit, axis or handedness conversion and no generated normals): one object per mesh node with `geometry_to_world`; control points added once per mesh; per-instance materials (`ufbx_node.materials`) before the mesh's; materials in file order (`typed_id`); faces of fewer than three corners skipped and counted; extra UV sets recorded by name; source unit from `UnitScaleFactor`; axes and FBX version recorded.
- glTF/GLB (`gltf_import.h`, fastgltf with external buffers and `KHR_mesh_quantization`): the default scene (else scene 0, else the root nodes) walked depth first, one object per mesh node with its world matrix; `TEXCOORD_0` with v = 1 − v (`v_flip`); later `TEXCOORD_n` recorded; stored `TANGENT`s counted; `TRIANGLES` imported, points and lines skipped, strips and fans refused; unit metre. Unnamed materials are `material<index>` and faces without a material use `default`, ordered after the file's materials, in glTF and FBX alike.
- `mesh_import.h`: `ImportMesh(bytes, file_name, settings)` checks, in order, `AutoUnwrapSettings` (`NotYetSupported`, before reading), the format (`.dae`, `.ply`, `.usd`, `.usda`, `.usdc`, `.usdz` → `ReleaseGap`; other extensions → `UnsupportedFormat`), parsing (`MeshParseError` with the line or the parser's message), duplicate material names (`DuplicateMaterialNames` with `{name: [indices]}`, or a merge into the first of the name with `allow_duplicate_material_names`, recorded as `merged_materials`), UVs outside 0–1 (`UVOutsideTile` with the tiles of the offending triangles' UV centroids, UDIM numbers or `u<i>_v<j>`), then units: `mesh_unit_scale` unset or 0 → centimetres per file unit from the file (FBX `UnitScaleFactor`, glTF 100, OBJ 1 since it states no unit), otherwise the given scale; `units {source, source_meters_per_unit, requested_mesh_unit_scale, scale_to_internal, from}` goes into the import report with the objects, materials, counts, flags and hashes. `CreateTextureSets(edit, result, source, channels)`, called inside one transaction, adds the mesh resource entry (`usage: mesh`; the project store keeps the original bytes under their SHA-256), sets `project.mesh` with the report and creates one texture set per material in file order (name and `original_name` = the material name, the project's default resolution, tile 1001, one ordinary stack). A refused import creates nothing.
- Orientation (`mask_image.h`): PNGs decode in file row order (row 0 = top = v 1); `TexelAt` maps a UV of tile 1001 to the texel of the UV raster convention (§5). The directional fixture checks that an asymmetric mask lands at the expected corners of a plane imported from OBJ and from glTF.
- Tangents (`tangents.h`, `phase1.5_mesh-tangents-certificate`): `ImportMesh` fills every corner's tangent slot with `ComputeTangents`, MikkTSpace (`genTangSpaceDefault`, compiled into `uzp_mesh`) run once per object over its triangles in order, on the corners' object-space positions, authored normals and `uv0`: xyz the unit tangent, w the bitangent sign. `InterpolateFrame(mesh, triangle, weights, mode = PerVertex)` gives a point's unnormalized frame (`PerVertex`: vB = Σ wᵢ signᵢ nᵢ × tᵢ; `PerFragment`: vB = sign(Σ wᵢ signᵢ) vN × vT), `ToTangentSpace` the exact inverse of `FromTangentSpace` = normalize(x vT + y vB + z vN), in the OpenGL (+v green) convention. The fixture re-run `uzp-normal-bake.exe` (`tests/mesh/normal_bake.cpp`, the prototype's bake over `src/mesh/`) equals the prototype's maps byte for byte and reproduces every residual of `parity/semantics/tangent-frame.json` against the Painter recordings (`tests/mesh/test_mesh_certificate.py`).
- Certificate (`certificate.h`): `Certify(mesh, {width, height})` reads the mesh (const) and returns the §4 counters, the per-set metrics on the texel grid of tile 1001 (`ImportSettings::certificate`, the texture sets' resolution; default 1024²) and the status; `ImportMesh` stores `CertificateToJson` as the report's `certificate`, beside `hashes` (§4 adds `uv.grid {width, height}`). Definitions: a zero length is below 1e-6; `degenerate_tbn` is a corner whose N, T or B is zero or non-finite or whose normalized frame spans |T · (B × N)| < 1e-3; `flipped_handedness` is a sign of −1; `coincident_opposite` counts triangles that overlap another with positive area in the same plane facing the opposite way, in scene space, whatever their vertices or diagonals; `zero_area_uv` is |UV area| ≤ 1e-12 and `flipped_uv` a negative (clockwise, v up) UV area; `outside_0_1` counts triangles with a corner outside the closed square. Per set (by material name): `overlap_px` counts texel centres covered twice (top-left rule, so shared edges are covered once); `islands` are components joined by edges equal in UV and scene position (stacked copies stay separate); density is sqrt(UV px area / surface cm²) per triangle with min, max and the surface-weighted median; `anisotropy_max` the largest singular-value ratio of the surface→UV map; `gap_px` the shortest distance between boundary edges of different islands (null with one island); `border_px` the shortest distance from a boundary edge end to the tile border. `status`: `fail` for non-finite or zero normals, zero tangents or bitangents, degenerate TBN, coincident opposite faces or UVs outside 0–1; else `warn` for flipped handedness, zero-area or flipped UV triangles, fanned n-gons or overlap; else `pass`. Gap, border, density and anisotropy are measured, not judged. Nothing in the mesh is modified.

## 4. Certificate (PRJ-09, PRJ-10)

Computed at import and stored with the mesh hash; never auto-repairs:

```json
{"corners": {"non_finite_normals": n, "zero_normals": n, "zero_tangents": n, "zero_bitangents": n, "degenerate_tbn": n, "flipped_handedness": n},
 "faces": {"coincident_opposite": n, "zero_area_uv": n, "flipped_uv": n, "ngons_triangulated": n},
 "uv": {"outside_0_1": n, "per_set": {"<set>": {"overlap_px": n, "islands": n, "density_px_per_cm": {"min":…, "p50":…, "max":…}, "anisotropy_max":…, "gap_px":…, "border_px":…}}},
 "mesh": {"objects": n, "triangles": n, "materials": [...], "units": {...}}, "hashes": {...}, "status": "pass|warn|fail"}
```

Diagnostic imports proceed with `warn`; the Assets3D production adapter (a pipeline-side script) refuses a paint round unless the manifest gates passed and the certificate has no `fail` (QG-02). UzPainter never repacks UVs.

## 5. UV-space rasterisation

A UzPainter compute/graphics pass renders the texturing mesh in UV space per set and tile into position, normal, tangent frame, island id and material id buffers (RGBA32F/R32Uint) with texel-centre coverage and a conservative coverage mask (supersampled); these feed projections, generators and bakers. Conservative rasterisation is not available in the vendored RHI (`uzengine-renderer/03-rhi-capabilities-for-texturing.md` §3), so coverage is computed by supersampling; island-edge behaviour is a Tier 0 item against Painter.

Implementation (`src/render/uv_raster.*`, `phase1.3_core-uv-raster`): a compute pass over backend-neutral corner buffers — position, corner normal, `uv0`, tangent xyz + sign, material id and island id, each with an explicit byte offset and stride into one of up to six buffers (interleaved or separate; no default stride) — and the triangles' corner ids; a texture set is selected by its material ids. Per UV tile (tile 1001 only in v1; every result carries its tile) it writes position, normal, tangent (w: interpolated sign) and bitangent (`sign · n × t` interpolated, the `PerVertex` frame) as RGBA32F, island and material ids and the covering triangle index as R32Uint (`0xFFFFFFFF` where no centre is covered; float buffers hold 0 there), and the conservative mask as R8Unorm. Texel convention as the Phase 0 prototype, which equals Painter's bakes on the normal-convention fixture: row 0 is v = 1, centres at ((col + ½)/W, 1 − (row + ½)/H). Texel-centre coverage includes the boundary; edge functions are evaluated in one canonical vertex order, so meshes are watertight (no centre on a shared edge is lost), and the lowest triangle index wins overlaps (atomic minimum, order-independent). The conservative mask holds every texel whose square the triangle's interior overlaps: the limit of supersampling at any density, evaluated exactly by a separating-axis test, because a finite sample grid misses triangles narrower than its spacing. IEEE-strict kernels and order-independent writes make the buffers byte-identical across runs and processes.

## 6. UV tiles

`ProjectWorkflow.Default` only in v1; UVs outside 0–1 fail import with the tile list, pointing to the release gap. The `TexturingMesh` and raster buffers are tile-indexed so `UVTile`/`TextureSetPerUVTile` can be added without changing the data model (Phase 4).

## 7. Reload (PRJ-08)

`project.reload_mesh(path, settings, cb)`: parse and certify the new mesh; match texture sets by material identity (ambiguity — renamed, split or merged materials — is an explicit error with the mapping proposal, never a silent attach); keep stacks and resources; re-rasterise; compare corner hashes per set and classify texels unchanged / moved / new / replaced; mark mesh maps, geometry masks, procedural caches and downstream receipts `invalid`; report `{sets: added, removed, renamed}` and the per-set region classes. One transaction; failure leaves the old mesh.

Implementation (`src/mesh/reload.h`, `phase1.6_mesh-reload`; tests `tests/mesh/reload_test.cpp`, `tests/mesh/test_mesh_reload.py`):

- `ReloadMesh(document, request, path, settings, read, source)` runs one `core::Execute` transaction: it re-derives the current mesh from its stored bytes (`ResourceReader`, the project store's blob reader) with the settings its import report records and checks the stored hashes (`RederiveMesh`), imports and certifies `path` (`ImportMesh`, every refusal applies), then `ApplyReload`. A failure — an import refusal, a mapping error, an unreadable blob, an invalid project or a commit sink that throws — commits nothing; the outcome is `failed` and `error` holds the typed exception. An identical mesh is a `no_op`.
- Material identity: a material whose name is in both meshes keeps its texture set (id, stacks, bindings); `material_mapping {old: new}` accepts one-to-one renames (the set takes the new name unless the user renamed it). Triangles are found again by object name and UV triangle. A material that disappears while its triangles reappear under one new material is a `rename`, under several a `split`, under a material that also receives others a `merge`; a kept material whose triangles reappear under a new material is a `split`. Any of these fails with `MaterialMappingError` and `{proposal: [{kind, from, to}], mapping: {old: new}}` (`mapping` holds the renames, ready for `material_mapping`). A material that disappears with no trace removes its set; one that appears on new triangles adds a set (default resolution, tile 1001, one stack with `new_set_channels`). Sets follow the new material order.
- Texel classes per set, on the set's resolution over tile 1001 with the §5 texel and coverage convention (row 0 = v 1, centre coverage boundary included, lowest triangle index wins), evaluated in float32 on the CPU: corner hashes are SHA-256 of the corner's `uv0` and of its `uv0`, scene-space position in centimetres, authored normal, tangent and sign and object transform; a triangle's keys hash its corners in cyclic order from the smallest. A texel covered before and after is `unchanged` (same full key), `moved` (same UV key) or `replaced`; covered only after `new`, only before `removed` (the fifth class, so every covered texel has one). `SetRegions` keeps the per-texel classes; the report and `invalid_report` carry the counts and the grid.
- Invalidation (kept and flagged, never deleted): when the texturing mesh's geometry changed anywhere (the positions, uvs, corner-normals or triangulation hash, or the effective unit scale) or a set's texels changed, every mesh-map binding of the set gets `invalid` and `invalid_report {reason: mesh_reload, mesh {from, to}, changed, regions}` (bakes and imported maps depend on the whole mesh), and every procedural reference in its stacks (procedural fill sources, generator and filter effects) gets `invalid` and `invalid_report` in its `extra` members, which the manifest writes beside its fields. A `Mesh` geometry mask with items gets the same flags when the set's UV coverage changed or the UV triangles of an object it names changed. Receipts live outside the project: `ReceiptInvalidated(header, project)` is true when a receipt read a mesh resource other than the project's mesh or the resource of an invalid binding; the report lists those hashes. The old mesh resource stays stored.
- Report (`ReloadReport::ToJson`, also the transaction's `returned.reload`): `{sets {added, removed, renamed [{from, to}]}, regions {<set>: {grid, unchanged, moved, new, replaced, removed}}, mesh {from, to, changed}, invalidated {mesh_maps, geometry_masks, procedural, receipt_resources}}`.

## 8. Auto-unwrap

`AutoUnwrapSettings` is accepted, recorded and rejected with `NotYetSupported` at import (xatlas exists in UzEngine but is not Painter's unwrapper; equivalence is unproven). Release gap.

## 9. Settling evidence (Phase 1, node P1-MESH)

Fixtures: mirrored UVs, hard edges, negative OBJ indices, n-gons, duplicate material names, instances/transforms, units, multi-set body, coincident opposite faces (the hat lesson `A3D\Docs\Pipeline\Licoes\bake-normais-tbn-por-canto.md`); reload/rename/split fixtures that preserve or deliberately reject bindings; the normal-convention fixture across Painter, UzPainter and UzEngine.

The fixtures live in `tests/mesh/` (`zig build mesh-tests` for the native cases of `uzp-mesh-tests.exe` and `uzp-mesh-reload-tests.exe`, `python -m pytest tests/mesh` for the rest). The P1-MESH acceptance run, which maps each fixture above to its test and records the normal-convention re-run over the production importer and production tangent frames, is `parity/reports/phase1/mesh-loader.md`. UzEngine appears there only as an external consumer: its own executables run as separate processes, and no include or library path of any UzPainter target reaches a UzEngine checkout (`tests/mesh/test_mesh_loader.py`, the `build-path` rule of `tools/vendoring/vendor_check.py`).
