# Owner questions and answers

Consolidated from `docs/analysis/architecture-discussion/05-resolution.md` §4 and answered by the owner on 2026-10-10 (`06-round4-changes.md`). Every answer is recorded as an accepted rulebook decision under `.rulebook/decisions/`. Where an answer changed an earlier record, the earlier decision is marked superseded and points to its successor: 004 → 019 (D2), 008 → 018 (D6), 014 → 021 (D12). Work consistent with a recorded decision proceeds; only an operation that would change one waits for the owner.

| Q1 | Equality contract | Exact equality is the rule; any divergence is accepted only through an owner-approved exception with evidence, recorded in the exception register (`architecture/14-parity-testing.md` §5). No preset tolerances; diagnostic metrics never grant an exception. Refines decision 001 (acceptance, still accepted) and D13 (015) | Closed 2026-10-10 | 017 |
| Q2 | Render reference | **Painter's Iray** is the render-parity target, not the realtime viewport: a clean-room path tracer (public path-tracing literature; NVIDIA MDL specification and the BSD-3 MDL SDK allowed; nothing from Adobe or Iray internals) on DX12 DXR and Vulkan ray tracing; converged Iray references captured on the owner's machine into the private oracle store with scene, camera, environment, sample count and seed fixed where Painter exposes them. Iray is stochastic, so pixel-exact equality is not achievable: the comparison is on converged references and goes through the Q1 exception register. The realtime viewport stays as the human preview and a fast check | Closed 2026-10-10 | 018 (supersedes 008) |
| Q3 | Shader implementation route and oracle use | Clean room (decision 002): public literature plus black-box calibration; Adobe's shader library, shader sources and `.py` sources off-limits; Painter stays installed as the private oracle | Closed 2026-10-10 | 002 |

| Q6 | Migration mechanism | Rebuild through Painter's documented API while it is installed, proven by output equality; no `.spp` reader | Closed 2026-10-10 | 020 |

UzEngine may consume UzPainter as a submodule in the future | Closed 2026-10-10 | 021 (supersedes 014) |
